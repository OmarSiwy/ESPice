Chapter 9 — System Tasks & Functions

9.1 Overview

Verilog-AMS HDL is a superset of IEEE Std 1364-2005 Verilog HDL and hence all the system tasks in IEEE Std 1364-2005 are supported. Verilog-AMS adds several system tasks and system functions. In addition, Verilog-AMS HDL extends the behavior of several Verilog system tasks and functions including allowing some of them to be used in an analog context.

9.3 System Tasks/Functions in the Analog Simulation Cycle

The analog simulation cycle iteratively evaluates the analog blocks in an analog macro process until convergence. The behavior of a system task or function during the iterative evaluation process is stated in the relevant section, if required. A call to a system task or function in an analog block during an iteration that is rejected shall cause no side-effects on the next iteration.

The analog engine supports additional analyses beyond a single transient analysis, including multiple transient analyses within a single simulation process. Behavior during different analysis types is stated in the relevant section where required.

9.4 Display System Tasks

9.4.1 Behavior of the Display Tasks in the Analog Context

display_tasks_in_analog_block ::=
    $strobe ( list_of_arguments ) ;
  | $display ( list_of_arguments ) ;
  | $monitor ( list_of_arguments ) ;
  | $write ( list_of_arguments ) ;
  | $debug ( list_of_arguments ) ;

Rules:

  • $strobe displays simulation data when the simulator has converged on a solution for all nodes. Arguments are displayed in the order they appear. Each argument can be a quoted string, an expression returning a value, or a null argument.
  • String contents are output literally, except when escape sequences are used to display special characters or specify a format for a subsequent expression.
  • A null argument (two adjacent commas ,,) produces a single space.
  • $strobe invoked without arguments prints a newline character.
  • $display provides the same capabilities as $strobe.
  • $write provides the same capabilities as $strobe, but with no trailing newline.
  • $debug displays its arguments for each iteration of the analog solver (including rejected iterations).
  • $monitor monitors and displays values of variables or expressions. For each accepted step, if a variable or expression in the argument list changes value compared with the last accepted step (except $abstime or $realtime), the entire argument list is displayed at the end of the time step as if reported by $strobe.

9.4.3 Format Specifications

The % character indicates the next character is a format specification. For each % (except %m, %%, and %l), a corresponding expression argument shall be supplied.

FormatDescription
%h or %HDisplay in hexadecimal format
%d or %DDisplay in decimal format
%o or %ODisplay in octal format
%b or %BDisplay in binary format
%c or %CDisplay in ASCII character format
%l or %LDisplay library binding information (displayed as "library.cell")
%m or %MDisplay hierarchical name (no argument consumed)
%s or %SDisplay as a string

Any expression argument with no corresponding format specification is displayed using the default decimal format in $strobe.

Format Specifications for Real Numbers

FormatDescription
%e or %EDisplay real in exponential format
%f or %FDisplay real in decimal format
%g or %GDisplay real in exponential or decimal format, whichever is shorter
%r or %RDisplay real in engineering notation using scale factors (see 2.6.2)

These have the full formatting capabilities available in the C language. For example, %10.3g sets a minimum field width of 10 with 3 fractional digits.

9.4.4 Hierarchical Name Format

The %m format specifier does not accept an argument. It causes the display task to print the hierarchical name of the module, task, function, or named block which invokes the system task containing the format specifier.

9.4.5 String Format

The %s format specifier is used to print ASCII codes as characters. The associated argument is interpreted as a sequence of 8-bit hexadecimal ASCII codes. The value is right-justified so the right-most bit of the value is the least-significant bit of the last character. Leading zeros are never printed.

9.4.6 Behavior During Iterative Solving

All display tasks, except $debug, shall not display output unless an iteration has been accepted.

9.4.7 Extensions to the Display Tasks in the Digital Context

For $strobe, $display, $write, and $monitor: the %r (or %R) format specifier may be used on real expressions in the digital context.

9.5 File Input-Output System Tasks and Functions

9.5.1 Opening and Closing Files

file_open_function ::=
    mcd = $fopen ( filename ) ;
  | fd = $fopen ( filename , type ) ;

file_close_task ::=
    $fclose ( multi_channel_descriptor ) ;
  | $fclose ( fd ) ;

$fopen opens the file specified by filename and returns either a 32-bit multichannel descriptor or a 32-bit file descriptor, determined by the absence or presence of the type argument.

filename is an expression that is a string literal, string data type, or an integral data type containing a character string.

type is a string expression of one of the forms in the table below. If type is omitted, the file is opened for writing and a multichannel descriptor mcd is returned. If type is supplied, the file is opened as specified and a file descriptor fd is returned.

The multichannel descriptor mcd is a 32-bit integer where a single bit is set indicating which file is opened. Bit 0 always refers to standard output. Output can be directed to multiple files by bitwise OR-ing multichannel descriptors. Bit 31 is reserved and shall always be cleared, limiting an implementation to at most 31 files via multichannel descriptors.

The file descriptor fd is a 32-bit value with bit 31 always set. Three file descriptors are pre-opened:

  • STDIN = 32'h8000_0000 (pre-opened for reading)
  • STDOUT = 32'h8000_0001 (pre-opened for append)
  • STDERR = 32'h8000_0002 (pre-opened for append)

File descriptors cannot be combined via bitwise OR.

Table 9-24 — Types for File Descriptors

ArgumentDescription
"r" or "rb"Open for reading
"w" or "wb"Truncate to zero length or create for writing
"a" or "ab"Append; open for writing at end of file, or create for writing
"r+", "r+b", or "rb+"Open for update (reading and writing)
"w+", "w+b", or "wb+"Truncate or create for update
"a+", "a+b", or "ab+"Append; open or create for update at end-of-file

If a file cannot be opened, a zero is returned for mcd or fd. Applications can call $ferror to determine the cause.

$fclose closes the file(s) specified by fd or mcd. No further I/O on closed file descriptors is allowed. $fopen shall reuse channels that have been closed.

9.5.1.1 Opening and Closing Files During Multiple Analyses

If a file is opened in a write mode in the first analysis and reopened in that write mode in a following analysis, content written from the following analyses shall be appended to content written during previous analyses.

9.5.1.2 Sharing of File Descriptors Between Analog and Digital Contexts

File I/O system functions and tasks in both contexts can use file descriptors opened in either context, if the file descriptors are opened for writing or appending.

9.5.2 File Output System Tasks

file_output_task ::=
    file_output_task_name ( fd [, list_of_arguments] ) ;

file_output_task_name ::=
    $fdisplay | $fwrite | $fstrobe | $fmonitor | $fdebug

Each formatted display task ($display, $write, $monitor, $strobe) has a file counterpart ($fdisplay, $fwrite, $fmonitor, $fstrobe, $fdebug). These accept the same arguments, except the first argument shall be either a multichannel descriptor or a file descriptor.

$fstrobe and $fmonitor work like their counterparts $strobe and $monitor, except they write to files using the file descriptor.

9.5.3 Formatting Data to a String

string_output_task ::=
    $swrite ( string_variable , list_of_arguments ) ;

variable-format_string_output_task ::=
    $sformat ( string_variable , format_string , list_of_arguments ) ;

$swrite is based on $fwrite and accepts the same arguments, except the first argument shall be a string variable to which the resulting string is written.

$sformat always interprets its second argument, and only its second argument, as a format string. This format argument can be a static string or a string variable. No other arguments are interpreted as format strings. $sformat supports all format specifiers supported by $display.

If not enough arguments are supplied for the format specifiers or too many are supplied, a warning is issued.

9.5.4 Reading Data from a File

Files opened with file descriptors can be read from only if they were opened with r or r+ type values.

9.5.4.1 Reading a Line at a Time

integer code;
code = $fgets( str, fd );

Reads characters from the file specified by fd into string variable str until a newline character is read and transferred to str, or an EOF condition is encountered. Returns the number of characters read in code, or zero on error.

9.5.4.2 Reading Formatted Data

integer code;
code = $fscanf( fd, format, args );
code = $sscanf( str, format, args );

$fscanf reads from the file specified by fd. $sscanf reads from the string str (which shall be a string variable, string parameter, or string literal).

Both functions read characters, interpret them according to a format, and store the results. The format string can contain:

  • White space characters (blanks, tabs, newlines, formfeeds) that cause input to be read up to the next non-white-space character.
  • An ordinary character (not %) that must match the next character of the input stream.
  • Conversion specifications: %, optional * (assignment suppression), optional decimal digit string (maximum field width), and a conversion code.
CodeDescription
%A single % is expected in the input; no assignment is done
dMatches an optionally signed decimal number
f, e, or gMatches a floating point number
rMatches a real number in engineering notation using scale factors (see 2.6.2)
sMatches a string (sequence of non-white-space characters)
mReturns the current hierarchical path as a string; does not read data

The number of successfully matched and assigned input items is returned in code; 0 on early matching failure, EOF if the input ends before the first matching failure or conversion.

9.5.5 File Positioning

integer pos;
pos = $ftell( fd );

Returns the offset from the beginning of the file of the current byte. Returns EOF on error.

code = $fseek( fd, offset, operation );
code = $rewind( fd );

Sets the position of the next I/O operation on fd:

  • operation = 0 — sets position equal to offset bytes
  • operation = 1 — sets position to current location plus offset
  • operation = 2 — sets position to EOF plus offset

$rewind(fd) is equivalent to $fseek(fd, 0, 0).

Repositioning cancels any $ungetc operations. Returns -1 on error, 0 on success.

9.5.6 Flushing Output

$fflush( mcd );
$fflush( fd );
$fflush( );

Writes any buffered output to the file(s) specified by mcd, to the file specified by fd, or if invoked with no arguments, to all open files.

9.5.7 I/O Error Status

integer errno;
errno = $ferror( fd, str );

A string description of the most recent error is written into str (which should be at least 640 bits wide). The integral error code is returned in errno. If the most recent operation did not result in an error, the return value is zero and str is empty.

9.5.8 Detecting EOF

integer code;
code = $feof( fd );

Returns a nonzero value when EOF has previously been detected reading fd; returns zero otherwise.

9.5.9 Behavior of File I/O Tasks During Iterative Solving

  • If a file is being read during an iterative solve and the iteration is rejected, the file pointer is reset to its position before the iterative solve started.
  • File write operations shall not be performed unless the iteration is accepted.
  • Exception: $fdebug write operations occur even during rejected iterations.
  • If the host system prevents the file position from being reset after a rejected iteration, a fatal error is reported.

9.6 Timescale System Tasks

Verilog-AMS HDL does not extend the timescale tasks defined in IEEE Std 1364-2005 Verilog HDL. $printtimescale and $timeformat are digital-context only.

9.7 Simulation Control System Tasks

9.7.1 $finish

finish_task ::=
    $finish [ ( n ) ] ;

If $finish is called during an accepted iteration, the simulator shall exit after the current solution is complete. Called during a rejected iteration, it has no effect. All appropriate final_step blocks are triggered.

If called from an analog initial block, the simulator shall exit without performing the simulation.

The optional expression n controls diagnostic messages (default is 1):

ParameterMessage
0Prints nothing
1Prints simulation time and location
2Prints simulation time, location, and statistics about memory and CPU time

If called from an analog initial block, the simulator reports that the call was made during initialization in place of the simulation time. If called from the analog context during a dc sweep, the current value of the swept variable is reported in place of the simulation time.

9.7.2 $stop

stop_task ::=
    $stop [ ( n ) ] ;

A call to $stop during an accepted iteration causes simulation to be suspended at a converged timepoint. Takes an optional expression argument (0, 1, or 2) as in the table above. $stop shall not be used within an analog initial block. The mechanism for resuming simulation is implementation-defined.

9.7.3 $fatal, $error, $warning, and $info

assert_severity_task ::=
    fatal_message_task
  | nonfatal_message_task

fatal_message_task ::=
    $fatal [ ( finish_number [ , message_argument { , message_argument } ] ) ] ;

nonfatal_message_task ::=
    severity_task [ ( [ message_argument { , message_argument } ] ) ] ;

severity_task ::= $error | $warning | $info

finish_number ::= 0 | 1 | 2
  • $fatal generates a run-time fatal assertion error, terminating the simulation. The first argument sets the diagnostic level as in $finish. Calling $fatal results in an implicit call to $finish. $fatal terminates the simulation without checking whether the iteration would be rejected.
  • $error generates a run-time error.
  • $warning generates a run-time warning, which can be suppressed in a tool-specific manner.
  • $info indicates that the assertion failure carries no specific severity.

Non-fatal severity tasks ($error, $warning, $info) called during a rejected iteration shall have no effect.

If $fatal is executed within an analog initial block, initialization may be aborted, and simulation shall not proceed past initialization. If $error is executed within an analog initial block, the message is issued and initialization continues, but simulation shall not proceed past initialization. $warning and $info only output their text message and do not affect initialization or simulation.

These tasks report the simulation run time. If called during a dc sweep, the current swept variable value is reported. If called from an analog initial block, the task reports that the call was made during initialization.

Each task can include additional user-specified information using the same format as $display.

9.9 Stochastic Analysis System Tasks

9.13 Probabilistic Distribution System Functions

9.13.1 $random and $arandom

random_function ::=
    $random [ ( random_seed ) ]

random_seed ::=
    integer_variable_identifier
  | reg_variable_identifier
  | time_variable_identifier

analog_random_function ::=
    $arandom [ ( analog_random_seed [, type_string] ) ]

analog_random_seed ::=
    integer_variable_identifier
  | reg_variable_identifier
  | time_variable_identifier
  | integer_parameter_identifier
  | [ sign ] decimal_number

type_string ::=
    "global"
  | "instance"

$random and $arandom return a 32-bit signed integer. $arandom is upwardly compatible with $random.

The random_seed argument may be omitted (simulator picks a seed). Within the analog context, it may be an analog integer variable. It is an inout argument: a value is passed in and a different value is returned. The variable should be initialized by the user and only updated by the system function.

$random shall always return the same stream of values given the same initial seed.

$arandom additionally supports analog_random_seed, which can be a parameter or constant. In that case, the parameter value is not updated; an internal seed is created and updated on each call. This allows $arandom to be used for parameter initialization. To get different random values when analog_random_seed is a parameter, override the parameter (see 6.3).

The type_string argument provides Monte-Carlo support and shall only be used within a paramset. If "global" (or not specified), one value is generated per Monte-Carlo trial. If "instance", one value is generated for each instance that references this value, with new values for each trial.

Example: where b > 0, the expression ($random % b) gives a number in the range [(-b+1):(b-1)].

integer rand;
rand = $random % 60;    // random number between -59 and 59

9.13.2 Distribution Functions

distribution_functions ::=
    $digital_dist_functions ( args )
  | $rdist_uniform ( seed , start_expression , end_expression [, type_string] )
  | $rdist_normal ( seed , mean_expression , standard_deviation_expression [, type_string] )
  | $rdist_exponential ( seed , mean_expression [, type_string] )
  | $rdist_poisson ( seed , mean_expression [, type_string] )
  | $rdist_chi_square ( seed , degree_of_freedom_expression [, type_string] )
  | $rdist_t ( seed , degree_of_freedom_expression [, type_string] )
  | $rdist_erlang ( seed , k_stage_expression , mean_expression [, type_string] )

seed ::=
    integer_variable_identifier
  | integer_parameter_identifier
  | [ sign ] decimal_number

type_string ::=
    "global"
  | "instance"

Rules:

  • All arguments are real values, except seed. For $rdist_exponential, $rdist_poisson, $rdist_chi_square, $rdist_t, and $rdist_erlang, the arguments mean, degree_of_freedom, and k_stage shall be greater than zero.
  • Each function returns a pseudo-random number whose characteristics are described by the function name.
  • The seed argument shall be an integer. If it is an integer variable, it is an inout argument. If a parameter or constant, an internal seed is created and updated on each call.
  • The functions shall always return the same value given the same seed.
  • All functions return a real value.
  • For $rdist_uniform, start shall be smaller than end.
  • For $rdist_normal: mean = 0 and standard_deviation = 1 generates Gaussian distribution.
  • The type_string provides Monte-Carlo support and shall only be used within a paramset (same semantics as for $arandom).

9.15 Analog Kernel Parameter System Functions

environment_parameter_functions ::=
    $temperature
  | $vt [ ( temperature_expression ) ]
  | $simparam ( param_name [, expression] )
  | $simparam$str ( param_name )

These functions return information about the current environment parameters as a real value.

$temperature

Takes no arguments. Returns the circuit's ambient temperature in Kelvin.

$vt

Optionally takes temperature (in Kelvin) as input. Returns the thermal voltage (kT/q) at the given temperature. Without the optional argument, returns the thermal voltage using $temperature.

$simparam

$simparam(param_name [, expression]) queries the simulator for a real-valued simulation parameter. param_name is a string value (string literal, string parameter, or string variable). If known, its value is returned. If not known and the optional expression is not supplied, an error is generated. If the optional expression is supplied, its value is returned when param_name is not known. Always returns a real value; integer parameters are coerced to real.

9.16 Dynamic Simulation Probe Function

dynamic_monitor_function ::=
    $simprobe ( inst_name , param_name [, expression] )

$simprobe() queries the simulator for an output variable named param_name in a sibling instance called inst_name. Both arguments are string values (string literal, string parameter, or string variable). The simulator looks for inst_name in the parent of the current instance (a sibling). If either cannot be resolved and the optional expression is not supplied, an error is generated. If the optional expression is supplied, its value is returned instead of raising an error.

Example:

module monitor;
    parameter string inst = "default";
    parameter string quant = "default";
    parameter real threshold = 0.0;
    real probe;
    analog begin
        probe = $simprobe(inst, quant);
        if (probe > threshold) begin
            $strobe("ERROR: Time %e: %s#%s (%g) > threshold (%e)",
                $abstime, inst, quant, probe, threshold);
            $finish;
        end
    end
endmodule
module top(d, g, s);
    electrical d, g, s;
    inout d, g, s;
    electrical gnd; ground gnd;
    SPICE_pmos #(.w(4u),.l(0.1u),.ad(4p),.as(4p),.pd(10u),.ps(10u))
        mp(d, g, s, s);
    SPICE_nmos #(.w(2u),.l(0.1u),.ad(2p),.as(2p),.pd(6u),.ps(6u))

        amonitor();

9.17 Analog Kernel Control System Tasks and Functions

9.17.1 $discontinuity

$discontinuity [ ( constant_expression ) ] ;

$discontinuity gives hints to the simulator about discontinuous behavior. It does not directly specify behavior. It shall be executed whenever the analog behavior changes discontinuously.

constant_expression indicates the degree of the discontinuity (non-negative): $discontinuity(i) implies a discontinuity in the i-th derivative of the constitutive equation with respect to either a signal value or time, where i must be a non-negative integer.

  • $discontinuity(0) — discontinuity in the equation
  • $discontinuity(1) — discontinuity in slope
  • $discontinuity(-1) — special form used with the $limit() function

Filter functions (transition(), slew(), laplace(), etc.) can smooth discontinuous behavior. Discontinuity created by switch branches and filters does not need to be announced.

Example (relay model):

module relay(c1, c2, pin, nin);
    inout c1, c2;
    input pin, nin;
    electrical c1, c2, pin, nin;
    parameter real r = 1;
    analog begin
        @(cross(V(pin,nin))) $discontinuity;
        if (V(pin,nin) >= 0)
            I(c1,c2) <+ V(c1,c2) / r;
        else
            I(c1,c2) <+ 0;
    end
endmodule

Example (triangle wave):

module triangle(out);
    output out;
    voltage out;
    parameter real period = 10.0, amplitude = 1.0;
    integer slope;
    real offset;
    analog begin
        @(timer(0, period)) begin
            slope = +1;
            offset = $abstime;
            $discontinuity;
        end
        @(timer(period/2, period)) begin
            slope = -1;
            offset = $abstime;
            $discontinuity;
        end
        V(out) <+ amplitude * slope *
            (4 * ($abstime - offset) / period - 1);
    end
endmodule

9.17.2 $bound_step

$bound_step ( expression ) ;

$bound_step() puts a bound on the next time step. It does not specify what the next time step is, but bounds how far the next time point can be from the present time point. The argument is the maximum time step (shall be non-negative). It does not return a value.

If the value is less than the simulator's minimum allowable time step, the simulator's minimum time step is used instead. The simulator shall ensure the next time step is no larger than the smallest $bound_step() argument currently active. The statement is ignored during non time-domain analyses.

Example (sinusoidal voltage source with 20 points per cycle):

module vsine(out);
    output out;
    voltage out;
    parameter real freq = 1.0, ampl = 1.0, offset = 0.0;
    analog begin
        V(out) <+ ampl * sin(2.0 * `M_PI * freq * $abstime) + offset;
        $bound_step(0.05 / freq);
    end
endmodule

9.17.3 $limit

limit_call ::=
    $limit ( access_function_reference )
  | $limit ( access_function_reference , string , arg_list )
  | $limit ( access_function_reference , analog_function_identifier , arg_list )

When the simulator has converged, the return value of $limit() is the value of the access function reference, within appropriate tolerances. For some analysis types or solution methods (e.g., damped Newton-Raphson), the return value may depend on the value of the access function and internal state. The simulator determines whether limiting should be applied and what the return value is on a given iteration.

When more than one argument is supplied, the second argument recommends a function to compute the return value. When the second argument is a string, it refers to a built-in function of the simulator.

Built-in Limit Functions

pnjlim — Intended for limiting arguments to exponentials. limexp() may be implemented through a function derived from pnjlim. Requires two additional arguments:

  • Third argument: step size vte (usually thermal voltage times emission coefficient)
  • Fourth argument: critical voltage vcrit (generally vte * ln(vte / (2 * Is)))

fetlim — Intended for limiting the potential across a MOS transistor oxide. Requires one additional argument:

  • Third argument: generally the threshold voltage of the MOS transistor

If the string refers to an unknown or unsupported function, the simulator determines the appropriate limiting algorithm as if no string had been supplied.

User-Defined Limit Functions

The second argument may be an identifier referring to a user-defined analog function. If limiting is needed, the simulator passes:

  • First argument: value of the access function reference for the current iteration
  • Second argument: the internal state (generally the return value from the previous iteration)
  • Third and subsequent arguments: passed through from $limit()

All arguments of the user-defined function shall be declared input. The user-defined function shall call $discontinuity(-1) when its return value is not sufficiently close to the value of its first argument.

Example (diode with user-defined pnjlim):

module diode(a, c);
    inout a, c;
    electrical a, c;
    parameter real IS = 1.0e-14;
    parameter real CJO = 0.0;

    analog function real spicepnjlim;
        input vnew, vold, vt, vcrit;
        real vnew, vold, vt, vcrit, vlimit, arg;
        begin
            vlimit = vnew;
            if ((vnew > vcrit) && (abs(vnew - vold) > (vt + vt))) begin
                if (vold > 0) begin
                    arg = 1 + (vnew - vold) / vt;
                    if (arg > 0)
                        vlimit = vold + vt * ln(arg);
                    else
                        vlimit = vcrit;
                end else
                    vlimit = vt * ln(vnew / vt);
                $discontinuity(-1);
            end
            spicepnjlim = vlimit;
        end
    endfunction

    real vdio, idio, qdio, vcrit;
    analog begin
        vcrit = 0.7;
        vdio = $limit(V(a,c), spicepnjlim, $vt, vcrit);
        idio = IS * (exp(vdio / $vt) - 1);
        I(a,c) <+ idio;
        if (vdio < 0.5) begin
            qdio = 0.5 * CJO * (1 - sqrt(1 - V(a,c)));
        end else begin
            qdio = CJO * (2.0 * (1.0 - sqrt(0.5))
                + sqrt(2.0) / 2.0 * (vdio * vdio + vdio - 3.0/4.0));
        end
        I(a,c) <+ ddt(qdio);
    end
endmodule

9.18 Hierarchical Parameter System Functions

hierarchical_parameter_system_functions ::=
    $mfactor
  | $xposition
  | $yposition
  | $angle
  | $hflip
  | $vflip

These functions return hierarchical information about the instance of a module or paramset. See 6.3.6 for how these parameters are specified and the automatic rules for instances with non-unity $mfactor.

  • $mfactor — the shunt multiplicity factor (number of identical devices combined in parallel)
  • $xposition, $yposition — offsets in meters of the location of the center of the instance
  • $hflip, $vflip — indicate the instance has been mirrored about its center
  • $angle — rotation in degrees counter-clockwise

These functions can also be used as targets in parameter alias declarations (see 3.4.7).

The returned value is computed by combining values from the top of the hierarchy down to the instance making the call:

9.19 Explicit Binding Detection System Functions

genvar_system_function ::=
    $param_given ( module_parameter_identifier )
  | $port_connected ( port_scalar_expression )

The return values of these functions are constant during a simulation; the value is fixed during elaboration. They can be used in genvar expressions controlling conditional or looping behavior of analog operators (see 4.5).

$param_given

$param_given(param_id) takes a single argument which must be a parameter identifier. Returns 1 if the parameter was overridden (by a defparam statement or by a module instance parameter value assignment), and 0 otherwise.

if ($param_given(tdevice))
    temp = tdevice + `P_CELSIUS0;
else
    temp = $temperature;

$port_connected

$port_connected(port_id) takes one argument which must be a port identifier. Returns 1 if the port was connected to a net (by order or by name) when the module was instantiated, and 0 otherwise. The port may be connected to a net with no other connections, but $port_connected shall still return 1.

module myclk(vout_q, vout_qbar);
    output vout_q, vout_qbar;
    electrical vout_q, vout_qbar;
    parameter real tdel = 3u from [0:inf);
    parameter real trise = 1u from (0:inf);
    parameter real tfall = 1u from (0:inf);
    parameter real period = 20u from (0:inf);
    integer q;
    analog begin
        @(timer(0, period))
            q = 0;
        @(timer(period/2, period))
            q = 1;
        if ($port_connected(vout_q))
            V(vout_q) <+ transition(q, tdel, trise, tfall);
        else
            V(vout_q) <+ 0.0;
        if ($port_connected(vout_qbar))
            V(vout_qbar) <+ transition(!q, tdel, trise, tfall);
        else
            V(vout_qbar) <+ 0.0;
    end
endmodule

module twoclk(vout_q1, vout_q2);
    output vout_q1, vout_q2;
    electrical vout_q1, vout_q1b;
    myclk clk1(.vout_q(vout_q1));
    myclk clk2(.vout_q(vout_q2));
endmodule

module top(clk_out);
    output clk_out;
    electrical clk_out;
    twoclk topclk1(.vout_q1(clk_out));
endmodule

9.20 Analog Node Alias System Functions

analog_node_alias_system_function ::=
    $analog_node_alias ( analog_net_reference , hierarchical_reference_string )
  | $analog_port_alias ( analog_net_reference , hierarchical_reference_string )

Both functions take two arguments. The analog_net_reference shall be a scalar or vector continuous node declared in the module containing the call. If it is a vector node, it shall reference the full vector node; bit select or part select is an error. The analog_net_reference shall not be a port or involved in port connections.

The hierarchical_reference_string shall be a constant string value (string literal or string parameter) containing a hierarchical reference to a continuous node. It shall not reference a node that is used as an analog_net_reference in another alias call. The reference follows the resolution rules in 6.7.

These functions shall only be used inside the analog initial block. They are re-evaluated each sweep point of a dc sweep as needed. They shall not be used inside conditional statements unless the conditional expression consists of terms that cannot change during simulation.

Return value: 1 if the hierarchical_reference_string points to a valid continuous node, 0 otherwise. If valid, the analog_net_reference is aliased to that hierarchical node and refers to the same circuit matrix position. If 0, the node is treated as a normal local continuous node.

A node aliased via $analog_port_alias() may be used as input to the port access function (see 5.4.3) and shall measure the flow through the port of the referenced instance.

If a node is involved in multiple calls, the last evaluated call takes precedence.

Validity rules for the hierarchical reference:

  • Shall refer to a scalar continuous node or scalar element of a continuous vector node
  • The discipline of the analog_net_reference and the resolved reference shall be compatible (see 3.11)
  • For $analog_port_alias(), the resolved reference shall be a port

Example:

module top;
    electrical a, b, c, gnd;
    ground gnd;
    resistor #(.r(1k)) r1(.p(a), .n(gnd));
    checker #(.n1_str("top.a")) ch1();
    analog V(a,gnd) <+ 5;
endmodule

module checker;
    electrical n1, n2;
    parameter string n1_str = "(not_given)";
    integer status;
    real iprobe, vprobe;
    analog initial begin
        // node n1 will be aliased to top.gnd
        status = $analog_node_alias(n1, "top.gnd");
        // Invalid: top.a is not a port. status = 0.
        status = $analog_port_alias(n2, "$root.top.a");
        // Overrides previous alias on n1: now aliased to top.a
        status = $analog_node_alias(n1, n1_str);
        // n2 is now aliased to port p of instance r1
        status = $analog_port_alias(n2, "top.r1.p");
    end
    analog begin
        // port current through top.r1.p: returns 5mA
        iprobe = I();
        // potential of top.a: returns 5V
        vprobe = V(n1);
    end
endmodule

9.21 Table Based Interpolation and Lookup ($table_model)

$table_model provides multidimensional interpolation and lookup on data sampled on isolines. Data is generated via parametric sweeping schemes. Dimensionality increases with nested parameter sweeps.

The interpolation process is recursive: for a lookup pair (x1, y1), the set of isolines in the outer dimension is searched to find the bracketing pair, then each isoline is interpolated in the inner dimension, and the resulting intermediate points are interpolated in the outer dimension. If the lookup point falls off the end of an isoline, its value is extrapolated.

Interpolation and extrapolation schemes operate in a single dimension at a time, so they may be specified per dimension.

Minimum data requirement: at least 2N points for N dimensions. Within the data set, each point shall be distinct in terms of its independent variable values. Duplicate points with the same dependent values are ignored (warning may be issued). Duplicate independent values with different dependent values cause an error.

table_model_function ::=
    $table_model ( table_inputs , table_data_source [, table_control_string] )

table_inputs ::=
    expression [, 2nd_dim_expression [, nth_dim_expression]]

table_data_source ::=
    file_name | table_model_array

file_name ::=
    string_literal | string_parameter

table_model_array ::=
    1st_dim_array_identifier [, 2nd_dim_array_identifier [, nth_dim_array_identifier]],
    output_array_identifier

table_control_string ::=
    "[interp_control[;dependent_selector]]"

interp_control ::=
    1st_dim_table_ctrl_substr_or_null [, 2nd_dim_table_ctrl_substr_or_null
        [, nth_dim_table_ctrl_substr_or_null]]

dependent_selector ::=
    integer

table_ctrl_substr ::=
    [table_interp_char][table_extrap_char [higher_table_extrap_char]]

table_interp_char ::=
    I | D | 1 | 2 | 3

table_extrap_char ::=
    C | L | E

9.21.1 Table Data Source

Data is specified as columns in a text file or as a set of arrays. A table of M dependent variables of dimension N is laid out in N+M columns, with independent variables in the first N columns (outermost to innermost) followed by dependent variables in the remaining M columns. Isoline ordinates are repeated for each point on the isoline.

File format: each sample point is separated by a newline, each column separated by spaces or tabs. Comments begin with # and continue to end of line. Blank lines are ignored. Numbers shall be real or integer.

When arrays are the data source, they are laid out conceptually the same way. Arrays may be specified via the concatenation operator or via array variable names. The state of the data source is captured on the first call; changes afterward are ignored.

Data may be provided in any order; the system will sort into isolines.

9.21.2 Control String

A set of comma-separated sub-strings followed by a semicolon and the dependent selector. The first group provides control over each independent variable (first sub-string = outermost dimension). The dependent selector is a column number (1 through M).

Each interpolation control sub-string has at most 3 characters.

Table 9-30 — Interpolation Control Character

CharacterDescription
IIgnore this input column
DClosest point (discrete) lookup
1Linear interpolation (default)
2Quadratic spline interpolation
3Cubic spline interpolation

Table 9-31 — Extrapolation Control Character

CharacterDescription
CConstant extrapolation (returns endpoint value)
LLinear extrapolation (default)
EError on extrapolation request (fatal error)

Users may use up to 2 extrapolation characters per dimension. With no extrapolation character, linear is default for both ends. One character applies to both ends. Two characters: the first applies to the lower coordinate end, the second to the higher coordinate end.

9.21.3 Example Control Strings

Control StringDescription
"" or omittedDefault: linear interpolation and extrapolation. Dimensionality assumed N, column N+1 is the dependent.
"1L,1L"2-D, linear interpolation and extrapolation in both dimensions
"1LL,1LL"Same, extrapolation specified for both ends in each dimension
"1LL,1LL;1"Same, dependent variable 1 specified explicitly (default when unspecified)
"D,1,3"Closest point outer, linear middle, cubic spline inner
"I,1CC,1CC;3"Ignore column 1, linear interpolation + constant extrapolation, dependent variable 3
"3,D,I,1;3"Cubic spline dim 3, closest dim 2, ignore column 3, linear innermost, dependent variable 3
"C,,3"3-D, equivalent to "1CC,1LL,3LL"

9.21.4 Interpolation Algorithms

  • Closest point lookup — returns the closest point; when equidistant from two bracketing samples, snaps away from zero.
  • Linear interpolation — simple linear interpolation between closest sample points on a given isoline.
  • Cubic spline interpolation — generates a spline for each isoline; extrapolation options are used for end-point derivatives. Linear extrapolation leads to a natural spline. Constant extrapolation sets end-point derivative to zero.
  • Quadratic splines — similar to cubic splines, more efficient evaluation with generally less favorable results.

Cubic splines are best for smoothly varying data (e.g., DC I-V characteristics). Linear interpolation is better for data with abrupt transitions (e.g., transient pulsed waveforms).

Using file-based data source:

    inout a, b;

        I(a, b) <+ $table_model(0.0, V(a,b), "sample.dat");
    end
endmodule

9.22 Connectmodule Driver Access System Functions and Operator

These functions are for Verilog-AMS mixed-signal connect modules only. They access drivers found in ordinary modules (not connect modules) and can only be called from connect modules.

Event detection keyword used with @ to detect updates to any driver of a signal:

Due to driver-receiver segregation, the value driving digital receivers must be specified. Default behavior (no explicit assignment) is equivalent to assign d_receivers = d_drivers;. Explicit specification:

These AMS-only functions access digital events scheduled onto a driver but not yet matured. They can create analog waveforms crossing a threshold at the same time the digital event matures. Only usable in the digital context of connect modules.

9.23.1 $driver_delay

driver_next_strength_function ::=
    $driver_next_strength ( signal_name , driver_index )
