Chapter 4: Expressions & Analog Operators

4.1 Overview

An expression combines operands with operators to produce a result that is a function of the values of the operands and the semantic meaning of the operator. Any legal operand (such as an integer or an indexed element from an array of reals) without an operator is also considered an expression. Wherever a value is needed in a Verilog-AMS HDL statement, an expression can be used.

Some statement constructs require an expression to be a constant expression. The operands of a constant expression consist of constant numbers and parameter names, but they can use any of the operators defined in Table 4-1, Table 4-14, and Table 4-15.

The following operators are legal when applied to real operands. All other operators are illegal with real operands.

The result of using logical or relational operators on real numbers is an integer value 0 (false) or 1 (true).

If a real expression is used for the replication factor of a concatenation, the expression will first be converted to an integer using the rules in 4.2.1.1.

4.2.1.1 Real to Integer Conversion

Real numbers are converted to integers by rounding the real number to the nearest integer, rather than by truncating it. If the fractional part of the real number is exactly 0.5, it shall be rounded away from zero.

Examples: 35.7 and 35.5 both become 36; 35.2 becomes 35. Converting -1.5 yields -2; converting 1.5 yields 2.

4.2.1.2 Integer to Real Conversion

Implicit conversion shall take place when an expression is assigned to a real. Individual bits that are x or z in the net or variable shall be an error.

4.2.1.3 Arithmetic Conversion

If either operand is real, the other operand is converted to real. Implicit conversion takes place when an integer number is used with a real number in an operand.

a = 3 + 5.0;      // 3 cast to 3.0, result is 8.0
b = 1 / 2;        // integer division, result is 0
c = 8.0 + (1/2);  // (1/2) is integer division (0), cast to 0.0, result is 8.0
d = 1 / 2.0;      // real division, result is 0.5

4.2.3 Expression Evaluation Order

Operators follow associativity rules. The operators &&, ||, and ?: shall use short-circuit evaluation: some operand expressions shall not be evaluated as long as the expression contains no analog operators and their value is not required to determine the final value. All other operators shall not use short-circuit evaluation.

An expression using relational operators yields 0 if false, 1 if true. Relational operators have lower precedence than arithmetic operators.

a < foo - 1     // same as a < (foo - 1)
foo - (1 < a)   // NOT the same as foo - 1 < a

4.2.6 Case Equality Operators

The case equality operators (===, !==) share the same precedence as the logical equality operators. These operators have limited support in the analog block (see 7.3.2).

4.2.7 Logical Equality Operators

Table 4-8 — Equality operators
OperatorDescription
a == ba equal to b
a != ba not equal to b

Both equality operators have the same precedence, which is lower than relational operators. The result is 0 if comparison fails, 1 if it succeeds.

4.2.8 Logical Operators

&& (logical and) and || (logical or) are logical connectives. The result is 1 (true) or 0 (false). && has greater precedence than ||, and both are lower than relational and equality operators.

The unary logical negation operator (!) converts a non-zero operand into 0 and a zero operand into 1.

a < param1 && b != c && index != lastone
// equivalent to:
(a < param1) && (b != c) && (index != lastone)

4.2.10 Reduction Operators

The reduction operators cannot be used inside the analog block and only have meaning in the digital context.

4.2.11 Shift Operators

Logical shift operators: << and >>. Arithmetic shift operators: <<< and >>> (cannot be used in an analog block).

The logical shift operators perform left and right shifts and fill vacated bit positions with zeroes. The right operand is always treated as unsigned.

integer start, result;
analog begin
    start = 1;
    result = (start << 2);   // result = 0100 (binary), i.e. 4
end
integer start, result;
analog begin
    start = 3;
    result = (start >> 1);   // result = 0001 (binary), i.e. 1
end

4.2.12 Conditional Operator

The conditional (ternary) operator is right associative.

conditional_expression ::=
    expression1 ? { attribute_instance } expression2 : expression3

If expression1 evaluates to false (0), expression3 is used as the result. If expression1 evaluates to true (nonzero), expression2 is used.

4.2.13 Concatenations

A concatenation joins bits from one or more expressions into a single value, expressed using braces { } with commas separating the expressions. Unsized constant numbers shall not be allowed in concatenations.

{1'b1, 3'b101}           // = 4'b1101
{1'b1, 1'b1, 1'b0, 1'b1} // equivalent
{ "hello", " ", "world" } // = "hello world"

Replication is a concatenation preceded by a non-negative, non-x, non-z constant expression (the replication constant):

{4{w}}            // same as {w, w, w, w}
{b, {3{a, b}}}    // same as {b, a, b, a, b, a, b}

A replication with a zero replication constant has size zero and is ignored, but shall appear only within a concatenation where at least one operand has a positive size. When a replication expression is evaluated, the operands are evaluated exactly once even if the replication constant is zero.

4.2.14 Assignment Patterns

The assignment pattern '{} specifies lists of expressions of a particular type, particularly for array assignments.

assignment_pattern ::=
    '{ expression { , expression } }
  | '{ constant_expression { expression { , expression } } }

constant_assignment_pattern ::=
    '{ constant_expression { , constant_expression } }
  | '{ constant_expression { constant_expression { , constant_expression } } }
parameter real data1[0:4] = '{3.4, 5.6, 2.3, 4.5, 7.1};
parameter real data2[0:4] = '{ 5{0.0} };

real measurements[0:2];
real a, b, c;
analog begin
    // ...
    measurements = '{a, b, c};
end

Contexts where array assignment patterns are allowed:

  • Analog operator arguments expected to be of type array (see 4.5.1)
  • The data_source argument of $table_model
  • Parameter array assignment in an instantiation
  • The RHS of an array variable or array parameter default assignment
  • The RHS of an array variable assignment
  • Array arguments in calls to user-defined functions

4.4 Signal Access Functions

Access functions access signals on nets, ports, and branches. There are two types: branch access functions and port access functions. The name of the access function is taken from the discipline of the net, port, or branch. Branch access functions use the () operator; port access functions use the < > operator.

The generic potential and flow access functions are also supported as alternatives to the discipline-specific access attribute (see 5.5.1).

When used in an expression, the access function returns the signal value. On the left side of a contribution statement, it assigns a value. Port access functions cannot be used on the left side of a contribution statement.

Table 4-16 — Access function examples (electrical discipline: V = potential, I = flow)

V(n1)Voltage of n1 relative to ground

I(n1)Current in the unnamed branch from n1 to ground

The argument list shall be a branch identifier, or a list of one or two net or port expressions. If two net expressions are given to a flow access function, they shall not evaluate to the same signal. If only one net expression is given, the second terminal is implicitly ground.

4.5 Analog Operators

Analog operators are functions that operate on more than just the current value of their arguments. They maintain internal state and their output is a function of both the input and the internal state. They are also referred to as analog filter functions.

They include: time derivative, time integral, delay operators, transition and slew filters (for removing discontinuities), Laplace and Z-transform filters, and limexp().

analog_filter_function_call ::=
    ddt ( analog_expression [ , abstol_expression ] )
  | ddx ( analog_expression , branch_probe_function_call )
  | idt ( analog_expression [ , analog_expression [ , analog_expression [ , abstol_expression ] ] ] )
  | idtmod ( analog_expression [ , analog_expression [ , analog_expression [ , analog_expression
        [ , abstol_expression ] ] ] ] )
  | absdelay ( analog_expression , analog_expression [ , constant_expression ] )
  | transition ( analog_expression [ , analog_expression [ , analog_expression
        [ , analog_expression [ , constant_expression ] ] ] ] )
  | slew ( analog_expression [ , analog_expression [ , analog_expression ] ] )
  | last_crossing ( analog_expression [ , analog_expression ] )
  | limexp ( analog_expression )
  | laplace_filter_name ( analog_expression , [ analog_filter_function_arg ] ,
        [ analog_filter_function_arg ] [ , constant_expression ] )
  | zi_filter_name ( analog_expression , [ analog_filter_function_arg ] ,
        [ analog_filter_function_arg ] , constant_expression
        [ , analog_expression [ , constant_expression ] ] )

4.5.1 Vector or Array Arguments to Analog Operators

Certain analog operators require arrays or vectors as arguments: Laplace filters, Z-transform filters, noise_table(), and noise_table_log(). An array can be passed as an array identifier (e.g. an array parameter or variable) or an array assignment pattern (see 4.2.14).

4.5.2 Analog Operators and Equations

Simulators formulate the system in terms of first-order differential equations and solve numerically using iterative approaches. Each equation shall have a tolerance defined. Analog operators may require new equations and unknowns; the simulator attempts to determine the appropriate tolerance from context, or operators can specify tolerances explicitly.

4.5.3 Time Derivative Operator — ddt

Computes the time derivative of its argument.

FormDescription
ddt(expr)Returns d/dt of expr. In DC analysis, returns 0.
ddt(expr, abstol)Same, with explicit absolute tolerance.
ddt(expr, nature)Same, with tolerance derived from nature.

The absolute tolerance applies to the output of the ddt operator and is the largest signal level considered negligible.

4.5.4 Time Integral Operator — idt

Computes the time-integral of its argument.

FormDescription
idt(expr)Returns the integral from t0 to t of expr, plus c (initial value determined by the simulator, generally the DC value that makes expr equal to zero).
idt(expr, ic)Same, but c is the value of ic at t0.
idt(expr, ic, assert)Returns the integral from ta to t of expr, plus c (value of ic at ta), where ta is the time when assert was last nonzero (or t0 if never nonzero).
idt(expr, ic, assert, abstol)Same, with explicit absolute tolerance for integration error.
idt(expr, ic, assert, nature)Same, with tolerance from specified nature.

In DC or IC analyses, idt() returns the initial condition (ic) if specified. If not specified, the idt operator must be within a negative feedback loop that forces its argument to zero; otherwise the output is undefined.

With initial conditions but without assert, idt() returns the ic value on the initial point of a transient analysis. With both ic and assert, idt() returns the ic during DC and IC analyses and whenever assert is nonzero. Once assert becomes zero, idt() returns the integral starting from the last instant where assert was nonzero.

The absolute tolerance applies to the input of the idt operator.

// Simple opamp modeled as an integrator
module opamp(out, pin, nin);
    output out;
    input pin, nin;
    voltage out, pin, nin;
    analog
        V(out) <+ idt(V(pin,nin));
endmodule
// Periodic ramp waveform using idt with assert
module ramp_generator(out);
    output out;
    voltage out;
    integer reset;
    analog begin
        reset = 0;
        @(timer(1, 1))
            reset = 1;
        V(out) <+ idt(1.0, 0, reset);
    end
endmodule

4.5.5 Circular Integrator Operator — idtmod

Converts an expression argument into its indefinitely integrated form, similar to idt, but with modular output.

FormDescription
idtmod(expr)Returns the integral from t0 to t of expr, plus c (determined by simulator).
idtmod(expr, ic)Same, but c is ic at t0.
idtmod(expr, ic, modulus)Returns k where 0 <= k < modulus, and integral + ic = n * modulus + k.
idtmod(expr, ic, modulus, offset)Returns k where offset <= k < offset + modulus.
idtmod(expr, ic, modulus, offset, abstol)Same, with explicit absolute tolerance.
idtmod(expr, ic, modulus, offset, nature)Same, with tolerance from specified nature.

The initial condition defaults to zero if not specified. The modulus shall evaluate to a positive value. If modulus is not specified, idtmod() behaves like idt(). The default for offset is zero.

The output of idtmod() remains in the range: offset <= idtmod < offset + modulus.

The following relationship holds at all times: if y = idt(expr, ic) and z = idtmod(expr, ic, modulus, offset), then y = n * modulus + z (n is an integer), where offset <= z < modulus + offset.

// VCO using circular integrator
phase = idtmod(fc + gain*V(in), 0, 1, 0);
V(OUT) <+ sin(2*`M_PI*phase);

4.5.6 Derivative Operator — ddx

Provides access to symbolically-computed partial derivatives of expressions in the analog block.

ddx( expr, unknown_quantity )

Where:

  • expr — the expression for which the symbolic derivative is calculated.
  • unknown_quantity — the branch probe (voltage or current probe) with respect to which the derivative is computed.

Returns the partial derivative of expr with respect to the unknown indicated by the second argument, holding all other unknowns fixed, evaluated at the current operating point. The second argument shall be the potential of a scalar net or port, or the flow through a branch.

If the expression does not depend explicitly on the unknown, ddx() returns 0. No tolerance is required because the derivative is computed symbolically.

// Diode conductance via ddx
module diode(a,c);
    inout a, c;
    electrical a, c;
    parameter real IS = 1.0e-14;
    real idio;
    (*desc="small-signal conductance"*)
    real gdio;
    analog begin
        idio = IS * (limexp(V(a,c)/$vt) - 1);
        gdio = ddx(idio, V(a));
        I(a,c) <+ idio;
    end
endmodule
// Diode with series resistance: effective conductance
module diode(a,c);
    inout a, c;
    electrical a, c;
    parameter real IS = 1.0e-14;
    parameter real RS = 0.0;
    real idio, gdio;
    (*desc="effective conductance"*)
    real geff;
    analog begin
        idio = IS * (limexp((V(a,c)-RS*I(a,c))/$vt) - 1);
        gdio = ddx(idio, V(a));
        geff = gdio / (RS * gdio + 1.0);
        I(a,c) <+ idio;
    end
endmodule
// Voltage-controlled current source: partial derivatives
module vccs(pout,nout,pin,nin);
    inout pout, nout, pin, nin;
    electrical pout, nout, pin, nin;
    parameter real k = 1.0;
    real vin, one, minusone, zero;
    analog begin
        vin = V(pin,nin);
        one = ddx(vin, V(pin));        // +1
        minusone = ddx(vin, V(nin));    // -1
        zero = ddx(vin, V(pout));       //  0
        I(pout,nout) <+ k * vin;
    end
endmodule

4.5.7 Absolute Delay Operator — absdelay

Implements absolute transport delay for continuous waveforms. (Use transition() for discrete-valued waveforms.)

absdelay( input, td [, maxdelay ] )

input is delayed by td. td shall be positive. If the optional maxdelay is specified, td can vary; if td exceeds maxdelay, maxdelay is used instead. If maxdelay is not specified, the value of td when first evaluated is used and future changes to td are ignored.

In DC and operating point analyses, absdelay() returns the value of its input.

In AC and small-signal analyses:

Output(w) = Input(w) * e^(-j*w*td)

In time-domain analyses:

Output(t) = Input( max(t - td, 0) )

4.5.8 Transition Filter — transition

Smooths out piecewise constant waveforms by controlling rise and fall times and adding delay.

transition( expr [, td [, rise_time [, fall_time [, time_tol ] ] ] ] )

The input expression is expected to be piecewise constant. transition() forces positive transitions to occur over rise_time and negative transitions over fall_time (after an initial delay of td). td models transport delay; rise_time and fall_time model inertial delay.

transition() returns a real number describing a piecewise linear function over time. The function causes the simulator to place time-points at both corners of a transition.

All optional parameters shall be non-negative if specified. td defaults to 0. If only rise_time is specified, it is used for both rise and fall. If neither rise_time nor fall_time are specified (or are zero), they default to `default_transition. If `default_transition is not specified, a negligible but non-zero transition time is used.

In DC analysis, transition() passes the value of expr directly to its output.

In AC analysis, transition() has approximately unity transmission for all frequencies.

If interrupted on a rising transition:

  • If the new destination is below the current value, transition() uses the old destination as the origin.
  • If the new destination is above the current level, the first origin is retained.

New transitions specified before a previously scheduled transition starts cause deletion of any transitions that would follow the newly scheduled transition. An arbitrary number of transitions can be pending.

// QAM modulator
module qam16(in, out);
    input [0:3] in;
    output out;
    voltage [0:3] in;
    voltage out;
    parameter real freq = 1.0 from (0:inf);
    parameter real ampl = 1.0;
    parameter real thresh = 2.5;
    parameter real tdelay = 0 from [0:inf);
    localparam real ttransit = 1/freq;
    real x, y, phi;
    integer row, col;
    analog begin
        row = 2 * (V(in[3]) > thresh) + (V(in[2]) > thresh);
        col = 2 * (V(in[1]) > thresh) + (V(in[0]) > thresh);
        x = transition(row - 1.5, tdelay, ttransit);
        y = transition(col - 1.5, tdelay, ttransit);
        phi = `M_TWO_PI * freq * $abstime;
        V(out) <+ ampl * (x * cos(phi) + y * sin(phi));
    end
endmodule
// N-bit A/D converter
module adc(in, clk, out);
    parameter bits = 8, fullscale = 1.0, dly = 0, ttime = 10n;
    input in, clk;
    output [0:bits-1] out;
    electrical in, clk;
    electrical [0:bits-1] out;
    real sample, thresh;
    integer result[0:bits-1];
    genvar i;
    analog begin
        @(cross(V(clk)-2.5, +1)) begin
            sample = V(in);
            thresh = fullscale/2.0;
            for (i = bits - 1; i >= 0; i = i - 1) begin
                if (sample > thresh) begin
                    result[i] = 1.0;
                    sample = sample - thresh;
                end else begin
                    result[i] = 0.0;
                end
                sample = 2.0*sample;
            end
        end
        for (i = 0; i < bits; i = i + 1) begin
            V(out[i]) <+ transition(result[i], dly, ttime);
        end
    end
endmodule

4.5.9 Slew Filter — slew

Bounds the rate of change (slope) of a waveform. Used for generating continuous signals from piecewise continuous signals. (For discrete-valued signals, use transition().)

slew( expr [, max_pos_slew_rate [, max_neg_slew_rate ] ] )

max_pos_slew_rate shall be greater than zero. max_neg_slew_rate shall be less than zero. If max_neg_slew_rate is not specified, it defaults to the opposite of max_pos_slew_rate. If no rates are specified, slew() passes the signal through unchanged. If the rate of change of expr is less than the specified maximum slew rates, slew() returns the value of expr.

In DC analysis, slew() passes the value directly to its output. In small-signal analyses, the transfer function is 1.0 when not slewing and 0.0 when slewing.

4.5.10 Last Crossing Function — last_crossing

Returns the simulation time when a signal expression last crossed zero.

last_crossing( expr [, direction ] )

The optional direction shall be +1, -1, or 0. If 0 (default), returns the most recent time of either a rising or falling edge transition. If +1 (-1), returns the last time of a rising (falling) edge.

last_crossing() does not control the timestep; it uses linear interpolation to estimate the crossing time. It can be combined with cross() for improved accuracy.

Before the expression crosses zero for the first time, last_crossing() returns a negative value.

// Measure period of input signal
module period(in);
    input in;
    voltage in;
    integer crossings;
    real latest, previous;
    analog begin
        @(initial_step) begin
            crossings = 0;
            previous = 0;
        end
        @(cross(V(in), +1)) begin
            crossings = crossings + 1;
            previous = latest;
        end
        latest = last_crossing(V(in), +1);
        @(final_step) begin
            if (crossings < 2)
                $strobe("Could not measure period.");
            else
                $strobe("period = %g, crossings = %d",
                    latest-previous, crossings);
        end
    end
endmodule

4.5.11 Laplace Transform Filters

Implement lumped linear continuous-time filters. Each filter takes an optional parameter epsilon, which is a real number or a nature used for deriving an absolute tolerance (if needed). The zeros argument may be represented as a null argument (two adjacent commas ,,).

4.5.11.1 laplace_zp — Zero-Pole Form

laplace_zp( expr, zeta, rho [, epsilon ] )

zeta is a vector of M pairs of real numbers (real part, imaginary part) representing zeros. rho is a vector of N pairs representing poles in the same manner.

Transfer function:

          M-1
          PROD (1 - s / (zeta_k_r + j*zeta_k_i))
          k=0
H(s) = -------------------------------------------
          N-1
          PROD (1 - s / (rho_k_r + j*rho_k_i))
          k=0

If a root is real, its imaginary part shall be specified as zero. If complex, its conjugate shall also be present. If a root is zero, the associated term is implemented as s rather than (1 - s/r).

4.5.11.2 laplace_zd — Zero-Denominator Form

laplace_zd( expr, zeta, d [, epsilon ] )

zeta is a vector of M zero pairs (real, imaginary). d is a vector of N real coefficients of the denominator polynomial.

          M-1
          PROD (1 - s / (zeta_k_r + j*zeta_k_i))
          k=0
H(s) = -------------------------------------------
          N-1
          SUM  d_k * s^k
          k=0

4.5.11.3 laplace_np — Numerator-Pole Form

laplace_np( expr, n, rho [, epsilon ] )

n is a vector of M real coefficients of the numerator polynomial. rho is a vector of N pole pairs (real, imaginary).

          M-1
          SUM  n_k * s^k
          k=0
H(s) = -------------------------------------------
          N-1
          PROD (1 - s / (rho_k_r + j*rho_k_i))
          k=0

4.5.11.4 laplace_nd — Numerator-Denominator Form

laplace_nd( expr, n, d [, epsilon ] )

n is a vector of M numerator coefficients. d is a vector of N denominator coefficients.

          M-1
          SUM  n_k * s^k
          k=0
H(s) = --------------------
          N-1
          SUM  d_k * s^k
          k=0

4.5.11.5 Laplace Filter Examples

// H(s) = (1+s) / ((1 + s/(1-j)) * (1 + s/(1+j)))
V(out) <+ laplace_zp(V(in), '{-1,0}, '{-1,-1,-1,1});

// H(s) = s / (s^2 - 1)
V(out) <+ laplace_nd(V(in), '{0,1}, '{-1,0,1});

// Band-limited white noise: k / (s^2 - 1)^2
V(out) <+ laplace_zp(white_noise(k), , '{1,0,1,0,-1,0,-1,0});

4.5.12 Z-Transform Filters

Implement linear discrete-time filters. A filter with unity transfer function acts like a simple sample-and-hold sampling every T seconds with no delay. The zeros argument may be a null argument (,,).

Common arguments shared by all Z-transform filters:

  • T — period of the filter (mandatory, shall be positive).
  • tau — transition time (optional, shall be non-negative). If not specified, defaults to one unit of time as defined by `default_transition and the trailing corner is not resolved. If zero, output is abruptly discontinuous and shall not be directly assigned to a branch.
  • t0 — time of first transition (optional, defaults to t=0).

4.5.12.1 zi_zp — Zero-Pole Form

zi_zp( expr, zeta, rho, T [, tau [, t0 ] ] )

          N-1

          k=0

If a root is real, imaginary part shall be zero. If complex, its conjugate shall also be present. If a root is zero, the term is implemented as z rather than (1 - z/r).

4.5.12.2 zi_zd — Zero-Denominator Form

zi_zd( expr, zeta, d, T [, tau [, t0 ] ] )

          M-1

          k=0
H(z) = -----------------------------------------------
          N-1

4.5.13 Limited Exponential — limexp

limexp( expr )

Returns a real value which is the exponential of its argument. Internally limits the change of its output from iteration to iteration to improve convergence. On any iteration where the output change is bounded, the simulator is prevented from terminating the iteration. The simulator can only converge when the output of limexp() equals the exponential of the input.

The apparent behavior is not distinguishable from exp(), except that using limexp() to model semiconductor junctions generally results in dramatically improved convergence.

For other nonlinearities, the $limit() system function (9.17.3) provides a method to indicate nonlinearities to the simulator.

4.5.15 Restrictions on Analog Operators

Analog operators maintain internal state and must be evaluated every iteration to keep that state valid. ddx() is the only exception (it does not require maintained internal state). All analog operators are considered to have no state history prior to time t == 0.

  • Analog operators shall not be used inside conditional (if, case, or ?:) statements unless the conditional expression consists of terms that cannot change their value during the course of a simulation.
  • Analog operators shall not be used inside event-triggered statements.
  • Analog operators are not allowed in repeat, while, and non-genvar for looping statements.
  • Analog operators can only be used inside an analog block; not inside initial or always blocks, or inside a user-defined function.
  • It is illegal to specify a null argument in the argument list of an analog operator, except as specified elsewhere (e.g. Laplace/Z-transform zeros argument).

4.6.2 DC Analysis

analysis("dc") and analysis("static") return true for a single-point DC analysis and for every DC point in a sweep analysis. analysis("nodeset") returns true only during the phase of an operating point analysis in which nodeset values are enforced; this may occur in a single-point DC analysis or the first point of a multipoint DC sweep, but not for subsequent points.

During a DC sweep, variable values from one operating point are used as starting values for the next DC point. Variable values are not carried over between independent DC sweep analyses; variables are re-initialized to zero at the start of each new analysis.

4.6.3 AC Stimulus — ac_stim

ac_stim( [ analysis_name [, mag [, phase ] ] ] )

Returns zero during large-signal analyses (DC, transient) and on small-signal analyses whose names do not match analysis_name. The default analysis_name is "ac". When matched, models a source with magnitude mag (default 1) and phase phase (default 0, in radians).

4.6.4 Noise Functions

Several functions support noise modeling during small-signal analyses. They are only active in small-signal noise analyses and return zero otherwise. For large-signal noise during transient analyses, use $random() or $arandom().

analog_small_signal_function_call ::=
    ...
  | white_noise ( analog_expression [ , string ] )
  | flicker_noise ( analog_expression , analog_expression [ , string ] )
  | noise_table ( noise_table_input_arg [ , string ] )
  | noise_table_log ( noise_table_input_arg [ , string ] )

4.6.4.1 white_noise

white_noise( pwr [, name ] )

Generates white noise with a power of pwr. The spectral density does not depend on frequency. The optional name labels the noise source for output contribution summaries; sources with the same name from the same instance are combined.

I(a,b) <+ V(a,b)/R +
    white_noise(4 * `P_K * $temperature/R, "thermal");

4.6.4.2 flicker_noise

flicker_noise( pwr, exp [, name ] )

Generates flicker (1/f) noise with a power of pwr at 1 Hz, varying in proportion to 1/fexp. The optional name labels the noise source.

4.6.4.3 noise_table

noise_table( input [, name ] )

Interpolates a set of values to model a process where spectral density varies as a piecewise linear function of frequency. The argument input can be a vector or a string indicating a filename.

When input is a vector: pairs of real numbers (frequency in Hz, power). The vector can be an array parameter or an array assignment pattern.

When input is a filename: the file contains frequency/power pairs separated by newlines; numbers in each pair separated by spaces or tabs. Comments begin with # and end at newline. The file shall be text format with real or integer numbers. The filename shall be constant (string literal or string parameter).

The user is encouraged to specify pairs in ascending frequency order; the simulator shall sort them if needed. Each frequency value must be unique.

Piecewise linear interpolation is performed between the lowest and highest frequency. Below the lowest frequency, the power of the lowest frequency is returned. Above the highest, the power of the highest is returned.

4.6.4.4 noise_table_log

noise_table_log( input [, name ] )

Same as noise_table() except interpolation is logarithmic. For frequency f where f1 < f < f2:

P = pow(10, log10(p1) + (log10(p2)-log10(p1)) * (log10(f)-log10(f1)) / (log10(f2)-log10(f1)))

Below the lowest frequency, returns the lowest power; above the highest, returns the highest power.

noise_table_log produces a straight line on a log-log plot from just two points:

V(out) <+ noise_table_log('{1,1, 1e6,1e-6});

Whereas noise_table produces curves between interpolating points:

V(out) <+ noise_table('{1,1, 1e1,1e-1, 1e2,1e-2, 1e3,1e-3, 1e4,1e-4,
    1e5,1e-5, 1e6,1e-6});

4.6.4.5 Noise Model for Diode

I(a,c) <+ is*(exp(V(a,c) / (n * $vt)) - 1)
    + white_noise(2*`P_Q*I(<a>))
    + flicker_noise(kf*pow(abs(I(<a>)), af), ef);

4.6.4.6 Correlated Noise

Each noise function generates uncorrelated noise. Perfectly correlated noise is generated by using one noise function output for multiple sources. Partially correlated noise is generated by combining shared and unshared noise functions.

// Perfectly correlated noise
n = white_noise(pwr);
V(a,b) <+ c1*n;
V(c,d) <+ c2*n;
// Partially correlated noise
n1 = white_noise(1-corr);
n2 = white_noise(1-corr);
n12 = white_noise(corr);
V(a,b) <+ Kv*(n1 + n12);
I(b,c) <+ Ki*(n2 + n12);

4.7 User-Defined Analog Functions

A user-defined function returns a value for an expression. All functions are defined within modules.

4.7.1 Defining an Analog User-Defined Function

analog_function_declaration ::=
    analog function [ analog_function_type ] analog_function_identifier ;
        analog_function_item_declaration { analog_function_item_declaration }
        analog_function_statement
    endfunction

analog_function_type ::= integer | real

analog_function_item_declaration ::=
    analog_block_item_declaration
  | input_declaration ;
  | output_declaration ;
  | inout_declaration ;

analog_block_item_declaration ::=
    { attribute_instance } parameter_declaration ;
  | { attribute_instance } integer_declaration
  | { attribute_instance } real_declaration

An analog user-defined function declaration begins with analog function, optionally followed by the return type (real or integer; default is real), then the function name and a semicolon, ending with endfunction.

Restrictions on analog user-defined functions:

  • Can use any statements available for conditional execution.
  • Shall not use access functions.
  • Shall not use analog filter functions (analog operators).
  • Shall not use contribution statements or event control statements.
  • Shall have at least one formal argument declared.
  • All formal arguments shall have a data type declaration and a direction specification (input, output, or inout).
  • Shall not use named blocks.
  • Shall only reference locally-defined variables, variables passed as arguments, locally-defined parameters, and module-level parameters. If a locally-defined parameter with the specified name does not exist, the module-level parameter is used.
// Example 1: Determine max value
analog function real maxValue;
    input n1, n2;
    real n1, n2;
    begin
        maxValue = (n1 > n2) ? n1 : n2;
    end
endfunction
// Example 2: Area and perimeter of a rectangle (multiple outputs)
analog function real geomcalc;
    input l, w;
    output area, perim;
    real l, w, area, perim;
    begin
        area = l * w;
        perim = 2 * ( l + w );
    end
endfunction
// Example 3: Array inout argument
analog function real arrayadd;
    inout [0:1]a;
    input [0:1]b;
    real a[0:1], b[0:1];
    integer i;
    begin
        for(i = 0; i < 2; i = i + 1) begin
            a[i] = a[i] + b[i];
        end
    end
endfunction

4.7.2 Returning a Value from an Analog User-Defined Function

There are three ways to return a value:

4.7.2.1 Implicit Function Identifier Variable

The function declaration implicitly declares an internal variable with the same name as the function. This variable inherits the declared type, is initialized to zero, and can be used within the function body. The last value assigned to it is the return value. If never assigned, the function returns the initialized value of zero. A function shall always return a scalar numerical value.

maxValue = (n1 > n2) ? n1 : n2;

4.7.2.2 Output Arguments

An output argument returns more than one value. The argument passed to an output must be an analog variable reference. If defined as an array, the passed argument must be an analog variable or an array assignment pattern of analog variables of equivalent size. All output arguments are initialized to zero (resetting the passed argument to zero). During execution, they can be read and assigned. At the end, the last value assigned is written back to the corresponding analog variable reference.

4.7.2.3 Inout Arguments

Inout arguments pass a value into the function and return a (possibly different) value via the same argument. The argument must be an analog variable reference (or array assignment pattern for array arguments). Unlike output arguments, inout arguments are not initialized to zero. If not assigned during execution, the corresponding analog variable is left untouched.

Inout arguments are not "pass by reference" but more closely "copy in" and "copy out". Avoid passing the same analog variable reference to different inout and output arguments of the same function, as the results are undefined.

4.7.3 Calling an Analog User-Defined Function

analog_function_call ::=
    analog_function_identifier { attribute_instance } ( analog_expression { , analog_expression } )

The order of evaluation of arguments is undefined. Argument expressions are assigned to the declared inputs, outputs, and inouts in the order of their declaration.

Restrictions on calling:

  • Shall not call itself directly or indirectly (recursive functions are not permitted).
  • Shall only be called within the analog context (from an analog block or from within another analog user-defined function).
// Using maxValue
V(out) <+ maxValue(val1, val2);

// Using geomcalc (first two args are input expressions, last two are output variables)
dummy = geomcalc(l-dl, w-dw, ar, per);

// ERROR: V(a) is a probe, not a variable reference -- cannot be used as output argument
dummy = geomcalc(l-dl, w-dw, ar, V(a));

// Using arrayadd with array assignment pattern
x[0] = 5; x[1] = 10;
y = 3; z = 6;
dummy = arrayadd(x, '{y,z});
// Result: x[0] = 8, x[1] = 16
