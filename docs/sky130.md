# sky130 decks

What it takes to run the SkyWater sky130 PDK (`sky130A`, ngspice model
library `libs.tech/ngspice/sky130.lib.spice`) as written, with Verilog-A
golden models in the same deck. The target is the AnalogIOC flow, where
SpiceRack writes the decks and ngspice was the reference simulator.

## Capability audit

| Deck feature | Status |
|---|---|

| `.param` chains, subcircuit `.param` bodies and header defaults, `{expr}` instance parameters, `.if` | supported |

## What changed for it

**R cards that read node voltages** (`frontend/netlist.zig`
`behaviouralResistor`). In the ngspice dialect an R card whose value reads
`v(`, `i(`, `time`, `temper` or `hertz` becomes
`b<name> n1 n2 i={v(n1,n2)/(eq)*(m)} tc1=.. tc2=.. reciproctc=1`, exactly
ngspice's inpcom.c rewrite: the temperature factor divides the current and
`m=` multiplies it. A B card now takes `key=value` parameters after a braced
expression.

**Constant subtrees fold before the B tape** (`builder.zig`
`foldConstants`). A parameter spliced into a B expression arrives as its own
postfix, so `rbody` carried `mc_mm_switch*agauss(...)` and the arithmetic of
a dozen constants into a 64-op tape. Every constant subtree now folds to one
constant (distributions to their nominal), which also keeps sky130's poly
resistors inside the op budget.

**`pow()` in a B expression is |x|^y** (ngspice ptfuncs.c `PTpower`), also for
an integer exponent; only the `^`/`**` operator keeps the sign of x
(`PTpowerH`). sky130's `rend` cubes a negative `min(...)` with `pow()`: with
the signed cube `res_high_po_0p35` read 0.7 % off ngspice at low bias, now
1e-5.

**`.option seed=N` draws the distributions** (ngspice dialect, no `MONTE`
sweep). ngspice draws `agauss`/`gauss`/`unif`/`aunif` on every run; ESPice
draws them once from the seed (`Deck.draw_seed`, `variants.drawOnce`), so a
seed is one reproducible mismatch sample and a seed loop is a Monte Carlo
run. The seed is detected before the model cards are read, because the PDK's
bins are shared rows read once. Without a seed the draws stay nominal (ngspice
would draw a random sample). The generators differ, so seed N is a different
sample in each simulator; the distributions agree (below).

**What the AnalogIOC benches needed besides the PDK** (found running them):
a transient that lands within 100 ulps of t_stop ends there, as ngspice's
dctran.c does, instead of failing `TimestepTooSmall` on a 1e-23 s last step;
a PWL longer than the 64-point source table continues in sources of its later
segments instead of being cut at point 64 (the weight-tile clock phases have
~350 points); and a Verilog-A internal net publishes as `v(<instance>#<net>)`.

Ceilings: a top-level `.param` holding a distribution stays nominal (it is
read before the seed is known); a distribution inside a B expression folds to
its nominal, which matches ngspice for sky130 (its resistor mismatch reads 0
in ngspice Monte Carlo too); a constant `pow()` with a negative base inside a
B expression folds with C `pow` semantics.

## Parity with ngspice

Measured 2026-10-04 against nixpkgs ngspice 45 (`.spiceinit` with
`ngbehavior=hsa`), sky130A `8afc8346`, same decks, both simulators at their
default tolerances. DC is the largest pointwise difference over the sweep;
delays are 50 %-to-50 %.

| Check | tt | ss | ff |
|---|---|---|---|
| Inverter W=1/2 L=0.15, DC: max \|ΔVout\| / VDD | 1.3e-4 | 4.6e-4 | 4.8e-5 |
| Inverter chain, tran tpd (worst of four edges) | +0.18 % | +0.19 % | +0.15 % |
| 5T OTA (W/L 4/0.5, 20 µA, 200 fF) A0 / UGF / PM | 0.0000 dB / 0.000 % / 0.0000° | same | same |
| 5T OTA worst \|Δ\| over 1 Hz–10 GHz | 0.0024 dB / 0.011° | 0.0030 dB / 0.013° | 0.0020 dB / 0.009° |
| MIM 10×10 µm through 10 kΩ, 63 % time | 0.0000 % | 0.0000 % | 0.0000 % |
| `res_xhigh_po_0p35` / `res_high_po_0p35` L=10, ±1.8 V DC at −40/27/85 °C | ≤ 1.4e-5 | | |

tt_mm, nfet W=1 L=0.15 at Vgs 0.7 V, Vds 0.9 V, seeds 1–100 in each
simulator: mean Id 2.906 µA (ngspice) vs 2.921 µA, σ(ln Id) 0.274 vs 0.269
(ratio 0.98; the 95 % interval for 100 samples is about ±0.2).

The inverter delay is the one figure above 0.1 %: both simulators pick their
own timesteps, and the rising edge of the first stage (22 ps) is 40 fs late in
ESPice at the 2 ps maximum step. It is under the 1 % budget at every corner.
