# Xyce and VACASK — making the second and third reference real, 2026-09-10

`remaining-2026-09-10.md` §13 said the runner had "full `xyce` plumbing that has
never been exercised — every row reads `skip`". That was accurate about the
outcome and wrong about the cause. The plumbing works. Nobody had ever run it,
and a `skip` with no reason is indistinguishable from a fixture that was never
tried. This is the first run of the suite against three independent
simulators.

ngspice-only N/A column: `docs/perf/na-audit-2026-09-10.md`.

## Method

The suite is **280** fixtures (`benchmark/fixtures/*/*/circuit.sp`; the earlier
"264" undercounts). For each one the runner preflights each reference, times
`--iters` repeats, and compares that reference's spice3 raw against espice's
with the SAME rule for all three: per-variable RMS ≤ 1e-3 and max ≤ 1e-2,
normalised by max(peak, span, 1). No per-fixture tolerances, no per-reference
tolerances. A reference that refuses a deck now records **the diagnostic line
the reference itself printed**, not the word `skip`.

espice itself does not run 32 of the 280 (`.pz`, `.stb`, some SOI/HFET decks,
degenerate topologies, the two Verilog-A fixtures). Those rows have no
comparison to make against any reference and are reported as `-`, not as a
pass.

Two runner defects were found and fixed while doing this, both of the same
family as the `skip`-hides-everything problem:

- The reference preflight gated on a 1 MiB output capture. ngspice prints
  **4.7 MB** on `scaling/rc_ladder_100k`, so a fixture it runs perfectly was
  being recorded as a skip. The gate is back on exit status; only a FAILING
  preflight pays for a second, captured run to name the reason.
- A reference that exits 0 having written no raw was reported as `N/A`
  ("could not compare") rather than a skip ("nothing to compare"). ngspice does
  exactly this on `golden/temp` — it rejects `.temp -40 125 55`, finds no other
  analysis card, and exits 0 with no output file. This is the `B3` item from
  `na-audit-2026-09-10.md`.

Timings in the results table were taken with eight other agents on the box and
are indicative only. **The accuracy columns are unaffected by contention and are
the deliverable.**

### The device under test is pinned too

The main tree's `zig-out/bin/espice` was **rebuilt during a sweep** — HEAD moved
from `446268a` to `6c92803` ("bsim4: nominal temperature is 27 degC, not 25") at

reads FAIL 1.69e-3 in `baseline-446268a.md` and PASS 3.14e-6 here: that is the
espice fix landing, not a measurement artifact.

The published run was therefore repeated against a **snapshot copy** taken
after the rebuild. The two runs agree on every verdict, every disagreement and
every FAIL, so nothing was contaminated — but only the pin makes that
checkable.

## Xyce

### The dialect shims

Xyce is SPICE3-compatible on the circuit and diverges on ngspice's lexical and
output-control extensions. Three deck rewrites (`xyceDeck`, modelled on the
existing `kluDeck`) and four comparator rules. Every one of them changes how a
thing is SPELLED, never what it means.

| # | shim | why | site |
|---|---|---|---|
| 1 | strip ` $ ...` inline comments | ngspice's comment marker; Xyce spells it `;` and reads the comment as device fields — `Unrecognized parameter AC Too Many Terms for device VIN` | `xyceDeck` / `stripInlineComment` |
| 2 | drop `.print` / `.plot` / `.width` | output control only; the raw comes from `-r`. A `.print AC` beside a `.tran` is a hard Xyce error, and a `.print` naming an ngspice spelling Xyce has no symbol for aborts the run | `xyce_dropped_cards` |
| 3 | `dc=V` → `DC V` on a source card | ngspice takes the `=` form, Xyce only the positional form — `Invalid DC value "=" for device VS` | `xyceDeck` |
| 4 | `sweep` → `v(v-sweep)` | Xyce names the DC-sweep scale `sweep` whatever is swept; ngspice and espice name it after the source | `scale_aliases` |
| 5 | plot class: `DC transfer characteristic` ≡ `DC operating point` ≡ `Operating Point` | Xyce runs `.op` as a one-point DC sweep. Unlisted plotnames are their own class, so tran-vs-DC is still refused | `plot_classes` |
| 6 | a reference scale column the candidate does not emit is not a missing signal | follows from 5: Xyce's `.op` carries a sweep column an operating point has no counterpart for. `any` still requires a real non-scale column to have matched | `comparePlots` |
| 7 | Xyce model-internal nodes are exempt from the coverage check | ngspice marks them `m1#drain` and VACASK `d1:a_int`, both already exempt; Xyce writes `q1_baseprime`, `d1_internal`, `t1_int1`, `m1_body`, `o1_branch1` — plain identifiers. `!` covers Xyce's synthesised devices (`ymil!k1_l1`) | `isInternalNode` / `xyce_internal_nodes` |

Shim 7 is a **closed list of 13 suffixes**, not a wildcard, on purpose: an
unlisted Xyce internal node makes its fixture read N/A, which is loud. A
wildcard would make it read PASS, which is silent — the exact failure mode this
work exists to remove.

### Shims deliberately NOT added

| candidate | why not |
|---|---|
| `.model NPN(level=4)` → `level=11` for VBIC | ngspice's level 4 is VBIC **1.2**; the only VBIC Xyce accepts in this build is level 11, VBIC **1.3**. Substituting one model version for another turns a disagreement into an unreadable one. Verified: levels 10, 12, 9 and 230 are all rejected outright, 11 runs. |
| `.model SW`/`CSW` → `VSWITCH`/`ISWITCH` | Xyce's switches are parameterised differently (RON/ROFF/VON/VOFF vs ngspice's VT/VH/RON/ROFF). Not a respelling. |
| `B1 out 0 V = expr` → `V={expr}` | ngspice allows spaces around `=`; Xyce requires braces. Rewriting a behavioural expression is a translator, not a shim, for one fixture. |
| LEVEL remaps for BSIM1/2, B3SOI, B4SOI, HiSIM2/HV, HICUM2 | same argument as VBIC, at greater distance — the parameter sets are not even nominally the same. |
| `X1:MID` ↔ `x1.mid` hierarchy separator | Xyce uses `:` for hierarchy, VACASK uses `:` for device-internal nodes. One rule cannot serve both, and `:` is already an exemption. **Known coverage gap**: subckt-internal nodes are not compared against Xyce. |

### Why Xyce refuses the decks it refuses

Every reason below is the diagnostic line Xyce printed, now carried into the
results table per row.

| class | mechanism | example message |
|---|---|---|
| analysis Xyce does not implement | `.pz`, `.tf`, `.disto`, `.sp`, `.stb`, `.pss`, `.pac`, `.pnoise`, `.pxf`, `.qpss`, `.envelope`, `.mc`, `.dcmatch`, `.matex`, `.trannoise`, and a `.temp`-only deck. The card is ignored, then no analysis remains | `Netlist error: No analysis specified.` |
| `.hb` | Xyce HAS harmonic balance and refuses to write it to a raw | `-r and -a outputs are not supported for Embedded Sampling, .HB, .LIN or .PCE` |
| model LEVEL not implemented | BSIM1 (L4), BSIM2 (L5), B3SOI (L11/12), B4SOI (L58), HiSIM2 (L68), HiSIMHV (L73), HICUM/L2 (L8), VBIC (L4), HFET1/2, MESA (NMF L2), VDMOS | `Model is required for device Q1 and no valid model card found.` |
| ngspice-only device feature | `R ... ac=` AC-only resistance; `SW`/`CSW` switch models; `B` source `V = expr`; LTRA/CPL/PLINE model parameters | `Unrecognized parameter AC for device R2`, `No model found for switch device S1`, `Parameter 0 not formatted correctly in .model PLINE` |

| Xyce crash | degenerate topology fixtures | `Netlist error: Empty matrix has been found, this linear solve has failed!` then SIGSEGV (exit 139) on `topology/current_cutset`; same on `topology/voltage_loop`. espice skips both by design, so nothing is lost — but a reference simulator that segfaults on a current cutset is worth knowing about. |

## VACASK

### 9 of 280, and why that is the honest number

**VACASK has no SPICE netlist reader.** Its deck language is a different
language, not a dialect: `vs (1 0) vsource dc=0 type="pulse" val0=0 val1=1`
against `vs 1 0 dc 0 pulse 0 1 ...`, devices loaded as OSDI modules, analyses
declared in a `control` block, DC sweeps expressed as a `sweep` wrapper around
an operating point. There is no shim that makes VACASK read `circuit.sp`; there
is only translation.

So VACASK runs exactly where a `<fixture>/vacask/runme.sim` exists:

| fixture | origin |
|---|---|
| `vacask/rc`, `vacask/graetz`, `vacask/mul`, `vacask/ring`, `vacask/c6288` | imported with the fixtures from VACASK's own benchmark suite |
| `op/voltage_divider`, `basic/rc_transient`, `dc_sweep/vin_sweep`, `devices/diode_iv_sweep` | **new, written here** |

The four new decks are hand translations held to `../circuit.sp` line for line,
with the mapping written into each deck's header comment. They were chosen to
prove the VACASK path end to end on one analysis each — operating point,
transient, DC sweep, nonlinear device — using `spice/*.osdi`, VACASK's build of
the SPICE models, so the model under test is the same model and only the
netlist language differs.

Two VACASK-side gotchas the decks document, both of which silently produce a
plausible-looking wrong answer:

- **`points` counts intervals, not points.** `.dc V1 0 10 0.5` is 21 points and
  `points=20`. Off by one and every sample lands between two of ngspice's.
- **identifiers cannot contain `-`,** so a VACASK sweep cannot be called
  `v-sweep`. The decks name it `vsweep` and `scale_aliases` maps the spelling.

### Deliberately not translated

`devices/mos6_inverter` is the highest-value FAIL row in the suite and it does
NOT get a VACASK deck. It is four instances of a 20-transistor hierarchical
subckt plus two MOS6 model cards; a transcription slip anywhere in it produces a
confident disagreement that is a deck bug, and Xyce already adjudicates that row.
A wrong third opinion is worse than none.

### Two upstream VACASK decks are not the same circuit as their `circuit.sp`

Found while checking the VACASK path. Neither is an espice defect and neither is
fixed here — the upstream deck is the authority and this tree does not have it.

**`vacask/mul` — different topology.** The FAIL on this row is not readable
until this is settled.

| | `circuit.sp` | `vacask/runme.sim` |
|---|---|---|
| d1 | `0 2` | `0 1` |
| d2 | `2 10` | `1 10` |
| c3 | `2 3` | `1 2` |
| d3 | `10 3` | `10 2` |
| d4 | `3 20` | `2 20` |

`circuit.sp` is a textbook Cockcroft–Walton ladder (nodes a,1,2,3,10,20). The
`.sim` has no node 3 at all and puts `c1` and `c3` in parallel between the same
two nodes, which is degenerate. They are not a relabelling of each other.

**`vacask/graetz` — different component value.** `rgnd1`/`rgnd2` are `1meg` in
`circuit.sp` and `1G` in `runme.sim`. Same topology, 1000× different leakage
path on the floating bridge.

### There is no fixture where ngspice is the outlier

**Zero** rows have espice FAILing ngspice while passing another reference. The
worry that a single reference was a single point of failure for correctness
claims does not reproduce: on every fixture two or more references scored,

### 14 of the 15 are Xyce apart from espice AND ngspice

The comparator only ever measures espice against a reference, but the triangle
inequality settles these anyway. On `scaling/rc_ladder_*`, espice and ngspice
agree to **2.2e-10** and Xyce is **8e-3** from espice, so Xyce is at least
8e-3 − 2.2e-10 from ngspice too. espice and ngspice are the pair; Xyce is apart
from both.

That is not a tolerance effect. Direct check on `scaling/rc_ladder_1k`, a purely
**linear** 1000-stage RC ladder, comparing the worst node `n1`:

| Xyce config | Xyce steps | Xyce vs espice | Xyce vs ngspice | espice vs ngspice |
|---|---:|---:|---:|---:|
| default | 127 | 7.98e-3 | 7.98e-3 | 1.45e-10 |
| `.options timeint reltol=1e-6 abstol=1e-12` | 2929 | 8.88e-3 | 8.88e-3 | 2.35e-10 |

Tightening Xyce's transient tolerances by three orders of magnitude and its
step count by 23× **does not reduce the disagreement**. The stimulus itself is
identical to nine digits at every sample (`v(in)` = 0.539999 on both at
t = 1.5146e-7), so the source is not the difference. On the very first step out
of a zero state, espice and ngspice give `v(n1)` = 4.9e-5 and Xyce gives
2.5e-5 — a factor of two, the signature of a different startup integration
formula rather than a different step size.

Read: **espice and ngspice share a time-integration formula (trapezoidal) and
solve this linear ladder identically; Xyce's default integrator does not, and
converging it harder does not bring it closer.** Nothing here is evidence
against espice. The same explanation covers `bypass/*`, `digital/clamp`,
`power/rectifier`, `tline/delay_line`, `scaling/parallel_inverters_*` and
`devices/mos6_simpleinv` — all transient, all with Xyce 1e-2-ish against
espice-vs-ngspice 1e-4-ish.

Two of the 15 are NOT that pattern and are worth a separate look:

- **`devices/jfet2`** is a DC sweep of a `NJF(LEVEL=2)` Parker–Skellern JFET.
  espice and ngspice agree to **1e-11**; Xyce's drain current is ~11× smaller
  (−8.9e-5 A vs −9.9e-4 A at Vds = 5 V) and it puts essentially the whole
  drain-source voltage across its internal `j1_drainprime` node. Xyce's level-2
  JFET is a different model, not a different tolerance. No action for espice.
- **`devices/mos9`** is a DC fixture where espice and ngspice agree to
  **3.5e-15** and Xyce is 9.9e-3 away — again a model-implementation gap
  (ngspice MOS level 9 vs whatever Xyce maps that level to), not integration.

### `vacask/graetz` is the fixture's fault

espice matches ngspice (7.05e-5) and Xyce (8.75e-5) and misses VACASK by
**4.27e-1**. That is the 1 MΩ vs 1 GΩ deck difference documented above, not a
simulator disagreement. Fix the deck and this row should join the 7 that are
scored by all three.

## Known coverage gaps, unfixed

- **Complex plots.** Any `.ac`, `.noise` or `.sp` output is refused outright by
  the comparator, for every reference. Xyce runs 12 AC and 4 noise fixtures and
  all 16 read N/A. This is `na-audit` B1 and the biggest single unlock left.
- **Multi-plot raws.** A deck with two analyses produces a raw the parser
  refuses. Xyce hits this too (`ngspice/lowpass_filter` writes
  `DC operating point` + `AC Analysis`).
- **Subckt-internal nodes are not compared against Xyce** — see the `:` row in
  "shims deliberately NOT added".
- **`benchmark/RESULTS.md` is untouched.** This run wrote only
  `docs/perf/baseline-3ref-2026-09-10.md` (`--out`), so the committed
  ngspice-only table is still there to diff against.
