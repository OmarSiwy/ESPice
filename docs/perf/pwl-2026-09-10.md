# PWL sources: the table lookup was O(n · 64), now it is O(log n)

A PWL source is a piecewise-linear table lookup in time. It cost **24,410 Ir
per vsource evaluation** on `bypass/burst_clock` — ngspice's whole PWL handling
costs about **308 Ir per timepoint**. Changing only the source card on one RC
deck moved the whole run from 11.8M (DC) to 112.0M (PWL(10)).

After: **~230 Ir per evaluation**, and `burst_clock` drops **−82.9%** whole-run.
Every PWL fixture is byte-for-byte unchanged, including across a rejected step.

## The cause

`vsource.va` declares `parameter real pwl_times[0:63]`. VerA scalarizes that
into 64 `f64` Model fields — there is no memory to index — and `lowerIndex`
turned a RUNTIME subscript into a 64-deep `select` chain:

```zig
const t27: S = (S.con(@floatFromInt(@intFromBool(hi[1] == 0)))).sel(S.con(model.pwl_timesZ5b0Z5d),
               (S.con(@floatFromInt(@intFromBool(hi[1] == 1)))).sel(S.con(model.pwl_timesZ5b1Z5d),
               ... 62 more ...
```

`sel` is a mask primitive, not a branch: every arm and every comparison is
evaluated on every read, regardless of where in the table `t` sits or how much
of it the card filled. The .va then scanned the table linearly — two loops,
two arrays each — so one evaluation cost `4 · (n−1)` chain reads at ~730 Ir
apiece. Quadratic in the wrong variable: linear in the FILLED length,
constant-factor 64 from the DECLARED extent.

## The three routes, priced

### 1. A runtime-indexable array in the Model POD

The honest fix "at the VerA layer": give VerA an array member instead of 64
scalars, so `a[k]` is a load.

**Cost at the GPU boundary.** `AGENTS.md` freezes Model/Instance PODs and the
scatter tapes there — "redesign host tables around them, never through them".
A real array member changes every affected device's Model struct, which is the
blob uploaded to the device and indexed by the baked PTX/AMDGCN images and by
the `.so` loader's layout guard. vsource itself is already GPU-ineligible
(`engine.gpuEligible` excludes it: it reads `$abstime`, so `core_reads_simstate`
is set), so this one device would not break a kernel — but the feature is not
device-scoped, and the first GPU-eligible model that used it would move its POD.

**And it buys nothing route 3 does not.** A load instead of a switch saves a few
instructions per read; it does not fix the SEARCH, which is the 113×. Rejected:
the largest blast radius of the three, aimed at the smaller half of the problem.

### 2. A native PWL source outside the VerA path

Precedent and plumbing exist — `src/devices/{ltra_native,txl_native,coupled_ltra}.zig`
are hand-written against the same contract.

**What it gives up.** Not GPU eligibility — vsource has none to give. It gives
up *uniform contract treatment*: `vsource.va` is ONE module carrying DC, PULSE,
SIN, EXP, PWL, SFFM and AM, the `analysis("static") && !analysis("tran")`
TRANOP/DCOP split, the AC/noise spec, 64 `@(timer(...))` breakpoints and the
`Dual` AD that produces the Jacobian row. A native PWL source either duplicates
all of that or splits the V card across two device types by waveform, which
`builder.zig` does not do.

**And it is a bandaid by the stated rule.** The select ladder is a property of
VerA codegen that every table-carrying model pays. Routing one device around it
leaves the other 37 paying. Rejected.

### 3. Fix the codegen — CHOSEN

Make a runtime array index emit one dispatch instead of an N-deep ladder, and
make the .va search the table instead of scanning it.

**Cost at the GPU boundary: zero.** Nothing about the Model/Instance POD, the
scatter tapes, the pattern CSC or `layoutHash()` moves. The array stays
scalarized into the same flat fields in the same order; only the *expression*
that reads one changes. Confirmed empirically: all 38 devices regenerated and
every fixture output is byte-identical.

## What landed

**VerA** (`pwl-source-vera`, commit `dcc93bc`), two files:

- `src/ir/lower.zig` `lowerIndex` — a runtime subscript now emits
  `$idx(lo, i, e_lo … e_hi)` instead of folding a `select` chain.
- `src/backend/codegen.zig` `emitIdx` — renders that as one Zig `switch` on the
  index. One dispatch, one element evaluated, `else` = element `lo` (§3.2.2
  leaves an out-of-range index undefined; element `lo` is what the chain's
  fallback was, so existing devices stay bit-identical). `pinLanes` on the index,
  for the same reason `emitTable` pins: the choice is one scalar decision.
- Same commit, a prerequisite: the subscript folds with `foldExpr(s, false)`,
  not `constEval`. A §3.4 parameter is overridable by the model card, so folding
  `a[pwl_len - 1]` through `pwl_len`'s DEFAULT bakes one element into the device
  and answers every other card with it — and here it failed loudly,
  `parameter integer pwl_len = 0` folding to `a[-1]` and reporting E0310 on
  legal source. Genvars and literals still fold; only overridable parameters
  stop.

**ARPice** (`pwl-source`, commit `7e2475b`), `src/devices/models/{vsource,isource}.va`:

- `t_last`/`v_last` read `pwl_times[pwl_len - 1]` directly instead of walking
  the table to find the last filled point.
- The interpolation scan became a bisection over `[klo, khi]`, invariant
  `pwl_times[klo] <= t_e < pwl_times[khi]`, exiting at `khi = klo + 1`.

The bisection picks the SAME segment the scan did. The scan assigned `out` for
every `k` with `t[k-1] <= t_e < t[k]`; for non-decreasing `t` exactly one `k`
satisfies both (`t[k] > t_e` is upward-closed from `khi`, `t[k-1] <= t_e` is
downward-closed to `khi`), so its last write was `khi` too — repeated knots
included, where the zero-width segment satisfies neither half. Same segment
through the same expression is the same bits, which is why the conformance
claim below is byte equality and not a tolerance.

### Why bisection and not ngspice's cursor

ngspice keeps a per-instance breakpoint cursor, which is O(1) amortised because
`t` advances monotonically within an accepted transient. It can afford to: its
table read is a real memory index, so the search is the whole cost.

Here the read is a switch dispatch, and the measured search is 4 dispatches at
n = 10, 6 at n = 64. A cursor would save ~3 of them — about 60 Ir per call at
n = 10, against the n-sweep below — and would buy an Instance field that has to
rewind correctly every time `stateCtl(.revert)` fires on a rejected step, in a
device that already declares `State`. 60 Ir is not worth a correctness surface
that no existing fixture exercises. Bisection is stateless, so it is right
across a reject *by construction*, not by testing. The `ponytail:` comment in
both .va files names the ceiling and the upgrade path (an Instance cursor
latched in `updateState` and reverted by `stateCtl(.revert)`, with the bisection
kept as the oracle it has to agree with) if a deck ever ships a 1000-point
table.

### Per-evaluation, and the scaling that is the actual claim

Same RC deck, `n` points spread over the same interval, Ir per NR iteration with
the DC control's 3,085 (before) / 3,081 (after) subtracted:

| n | before, Ir/eval | after, Ir/eval |
|---:|---:|---:|
| 2 | 3,116 | 118 |
| 4 | 8,910 | 181 |
| 8 | 20,504 | 223 |
| 16 | 43,726 | 272 |
| 32 | 90,321 | 334 |
| 64 | 183,952 | 423 |

Before: ~2,915 Ir per table point, dead linear. After: **+61 Ir per doubling** —
logarithmic, and the constant is the switch dispatch.

`burst_clock` independently: 4,082 NR iterations, Δ 99,641,121 Ir = **24,410 Ir
per evaluation removed**, matching the 24,452 Ir/call the audit reported. The
residual at 9 points is ~230 Ir/eval, against ngspice's ~308 Ir per timepoint.
At this deck's 2.0 Newton iterations per timepoint that is ~460 Ir/timepoint
versus ngspice's 308 — same order, and the remainder is the waveform dispatch
and the breakpoint list, not the table lookup. The algorithmic defect is closed.

`devices/hfet_inverter`: the audit's "13.8%" does not reproduce on this branch —
measured −0.35%. Its card is `pwl(0,0V 1ns,0V 1.005ns,1V 2ns,1V)`, which the
comma spelling reduces to 3 filled points, and the deck's 769 NR iterations are
dominated by two HFET level-5 kernels. The same card in isolation (RC probe,
2,054 iterations) costs 4,833 Ir/eval before and 89 after, so the mechanism is
there; it is simply a small share of that particular run.

### Boundaries

`src/builder.zig`, test *"V/I cards: the PWL bisection agrees with a linear
scan at every boundary"*. It transcribes the linear scan the .va used to run as
the oracle and drives `vsource.eval` directly at `x = 0` (where
`res[flow] = −source`), over five tables:

- a repeated knot mid-table (3 ns appears twice — a vertical step),
- a repeated knot at the SECOND point, so the step is the first segment,
- one point, and two points — the lengths where the bisection window is empty,
- `burst_clock`'s own 9-point table,

and for each, probe times that are: before the first point, `0`, each knot
exactly, each knot ±1 ulp, each segment midpoint, and far past the last point.
All four modifier combinations (`bare`, `td=1.5n`, `r=1n`, both) — `vsource.va`
does support both, they arrive as card kv through `applyKv` onto `pwl_repeat` /
`pwl_td`. 1,000+ comparisons, all agree.

`r=`/`td=` are also covered end-to-end by `/tmp`-side decks whose raw output is
byte-identical before and after.

### Across a rejected timestep

A deck with a 0.1 ns edge inside a microsecond grid, diode-loaded, at
`reltol=1e-6 trtol=1`:

```
Vin in 0 DC 0 PWL(0 0 1u 0 1.0001u 5 2u 5 2.0001u 0 3u 0 4u 0 5u 5 6u 5 7u 0)
R1 in a 100
D1 a 0 dm
C1 a 0 1n
.model dm D(is=1e-14 cjo=1p)
.options reltol=1e-6 abstol=1e-14 trtol=1 chgtol=1e-16
.tran 5n 7u
```

`ZP_TRAN_STATS=1`: `accepted=1887 attempts=1937 rej[newton=0 lte=50 state=0]`
— 50 LTE rejections, i.e. 50 times `t` moves backwards mid-segment. Identical
stats and **byte-identical raw** on both binaries. This is the failure mode a
cursor would introduce; the bisection reads no state, so there is nothing to
rewind.

## The inherited `wip:` commit

`0156a75` ("wip: interrupted by weekly quota") held the two .va files and
nothing else; the VerA half of the same attempt was left uncommitted in the
sibling worktree. Audited: the bisection is correct and the codegen change is
the right route. Two claims in its comments were wrong and are fixed here — it
asserted the switch is "a jump table, O(1) in the extent" without having built
it (it is one dispatch, which is the load-bearing part; "jump table" is an LLVM
choice, not a guarantee), and its repeated-knot argument said the zero-width
segment "matches neither rule" without establishing the uniqueness that makes
the scan and the bisection agree. Neither line of code changed. The `wip:`
commit is replaced by the commits this document references.

## Reproducing

```
# per-deck whole-run Ir
valgrind --tool=callgrind --cache-sim=no --branch-sim=no --callgrind-out-file=/dev/null \
  zig-out/bin/espice -b -r /dev/null benchmark/fixtures/bypass/burst_clock/circuit.sp

# per-evaluation: divide the delta by nr_iters
ZP_TRAN_STATS=1 zig-out/bin/espice -b -r /dev/null <deck>

# the boundary oracle
zig build test-app    # or test-suites; the PWL test lives in src/builder.zig
```

A baseline needs a matched build: revert
`src/devices/models/{vsource,isource}.va` to `446268a` AND
`../VerA/src/{ir/lower.zig,backend/codegen.zig}`, then `zig build` (~8 min, all
38 devices regenerate).
