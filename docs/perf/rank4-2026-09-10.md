# The rank-4 collapse specialisation — the only sound cut into the 488

2026-09-10, branches ARPice `rank4-collapse` / VerA `rank4-collapse-vera`.
Scope: `docs/perf/dual-ad-2026-09-10.md` §"Where the next real win is" item 3,
the last live item on `docs/perf/remaining-2026-09-10.md` §1.

**Result: pi100 −12.40%, mos6 −10.95%, 256 of 256 fixture raws byte-identical,
NR iteration counts unchanged.** 198 Ir per mos1 evaluation and 215 per mos6
evaluation, against a predicted ceiling of ~230 — 86% and 93% of the bound the
previous pass wrote down.

---

## 1. Why this is not the settled negative

The settled table kills *per-value derivative narrowing* on a device whose
internal nodes are LIVE: mos1's smallest correct universe is six, `@Vector(6,
f64)` lowers to ymm+xmm and measured a **21% loss**, and k=4 is unsound — 3150
bit mismatches at `rd = 12, rs = 9`.

This is a different claim. When `rd = rs = 0` — true on both gate decks and on
every MOSFET deck in the corpus bar one — `Builder.addDevice` has already run
`D.collapse` and aliased `di` onto `d` and `si` onto `s` **in the gather and
scatter tapes**. The internal nodes do not exist. Rank 4 is not an
approximation of rank 8; it is the rank.

The generated device says so itself. mos1's core reads `x[d]` and `x[s]` in
exactly one place each — `(x[d] − x[di]) · grd`, under `if (grd > 0)` — and its
`eval` reads the two branch-flow unknowns only inside
`if (comptime !S.collapse_applied)`. With `rd = 0` that branch is not taken and
those four unknowns are read **nowhere**. Their derivative lanes carry an
identically-zero gradient through the whole kernel. That is what makes the merge
exact rather than approximate, and it is also why the result came out
byte-identical rather than merely close.

## 2. How the partition is decided

Two halves, split along the comptime/runtime line, because the thing the host
needs is a *width* and widths are types.

**VerA, comptime — `collapse_full`** (`codegen.zig emitCollapseFull`). The same
union-find `collapse` runs, with every §5.6.1.3 retention flag set: the maximal
alias map. mos1/mos6 read `di → d`, `si → s`, `flow(d,di) → d`,
`flow(s,si) → s`; four distinct roots out of eight unknowns.
`tools/contract.zig` allowlists it and checks the two invariants the host relies
on — entries are fully resolved and alias downward — so `root[u] =
collapse_full[u] orelse u` is one lookup.

**ARPice, runtime — the instance test.** `ProtoStore.finalize` calls
`D.collapse(model, instance)` once per instance and compares it to
`collapse_full`. Equal ⇒ maximal ⇒ the reduced basis is sound. Anything else
merges strictly *less* and runs at full width; there is no partial narrowing.
This is the same call `Builder.addDevice` already makes, repeated at setup
rather than threaded through `append`, the three staging columns and the
type-erased `.so` path as a fourth column.

**The partition.** `finalize` stable-partitions the three staging columns so the
maximal instances come first and records `narrow_count` on the batch. It runs
**before** `buildTapes`, which is the only point where all three columns can
still be permuted together.

A **uniform** batch — every deck in the corpus, including `mos_series_r`, whose
two MOSFETs share one `RD=12 RS=9` card — takes an early return and nothing
moves, so instance order is untouched and with it both the order contributions
accumulate into a shared matrix slot and `ParamRef.index`. Only a genuinely
mixed batch is reordered, and there the alternative is no narrowing at all.

## 3. Where the second width lives

`evalRange` gains one comptime parameter:

```zig
fn evalRange(comptime D: type, comptime narrow: bool, sink: anytype, ...)
```

`narrow` picks the derivative basis and **nothing else**. Same body, same
`D.evalQ` call, same `DualFor` constructor, one comptime width apart — which is
AGENTS.md's scalar-oracle rule: the narrow path is the same kernel instantiated
at a different width, not a second code path. Three things follow from the
basis:

| | wide | narrow (mos1/mos6) |
|---|---|---|
| `S` | `DualFor(8, F, …)` — two ymm | `DualFor(4, F, …)` — one ymm |
| seed | `S.seed(lx[u], u)` | `S.seed(lx[u], lane[u])` |
| Jacobian read | `g[cu]` | `g[lane[cu]]` |
| columns stamped per row | every pattern bit | one per lane |
| `corr` | `@Vector(8, f64)`, indexed by unknown | `@Vector(4, f64)`, indexed by lane |

`DeviceBatch.evalInner` clamps `narrow_count` into the requested range and calls
`evalRange` twice, so a `ParEval` slice that straddles the boundary still runs
each instance under the basis its own collapse earned.

The **value** half stays per unknown, deliberately: `lx[d]` and `lx[di]` are the
same circuit node but not the same number once the limiter has moved `di`. Only
the derivative basis merges.

### The representative column — the part that decides byte-identity

A lane group's columns all resolve to one matrix slot, so exactly one of them
may stamp. *Which* one is not cosmetic. An unrelated column can resolve to the
same slot too — gate tied to drain, bulk tied to source, i.e. every current
mirror in the corpus — and then the slot's `+=` order decides the last bit.

The first implementation took the lowest set column, which moves mos1's row-`di`
stamp from column `di` (4) to column `d` (0), across `g` and `b`. Measured: four
decks drifted — `ngspice/mosamp` (4271 of 5175 samples, max 3.4e-9 absolute on a
deck whose own `vntol` is 10n) and `sweep/opamp_wl_{200,1000,5000}` (max 1.2e-7
relative, on AC real parts that are analytically zero). All four still PASSed
and the drift was deterministic, but it was drift.

The fix is one line and it has a reason: **the representative is the lowest
ALIAS, never the root**. Under maximal collapse the root is the port the physics
stopped reading — that structural zero is exactly what makes the merge exact —
and the alias is where the derivative actually lands. Stamping the alias puts
the value at the column the wide kernel put its nonzero on, and the columns
dropped are the ones that were carrying zeros. Byte-identical on all 256.

### Which devices get a second instantiation

Three gates, all from the settled table. On AVX2 every width from 1 to 4 is one
ymm, so the only thing that pays is crossing a register boundary:

- `w <= 4` — the narrow side must fit in one ymm (`@Vector(6,f64)` is the 21% loss).
- `n_u > 4` — the wide side must not *already* fit in one. This is the settled
  "narrowing popcount-2 values from 4 lanes to 2 saves zero" row, and it is why
  `diode` (n_u = 4, rank 2) is excluded: a real narrowing, no register saved.
- `n_u <= 8` — the regime the 488-Ir measurement was taken in.

| | n_u | collapsed rank | |
|---|---:|---:|---|
| mos1, mos2, mos3, mos6, mos9, bsim1, bsim3 | 8 | 4 | **narrow** |
| hfet2, jfet, mes | 7 | 3 | **narrow** |
| diode | 4 | 2 | wide — already one ymm |
| jfet2 | 10 | 6 | wide — k=6 is the measured loss |
| bjt | 14 | 4 | wide — `n_u > 8` |
| vdmos | 13 | 3 | wide — `n_u > 8` |
| bsim4va, bsimsoi, hicumL2, hisim2, hisimhv | 18–32 | 4–20 | wide — `n_u > 8` |

Lifting `n_u <= 8` would admit bsim4 (18 → 4, five ymm to one) and is the
obvious follow-up; it doubles a very large kernel's compile and nothing prices
those models on a gate deck today, so it is left as a ponytail note in
`canNarrow`.

**GPU stays wide.** `DeviceKernel.run` passes `narrow = false`. The partition
boundary is a per-batch scalar and the kernel ABI is frozen across the GPU
boundary; adding an argument for a win nobody has priced on a GPU is not the
trade. Noted in the code with its upgrade path.

### Bit-identity

- **`benchmark/fixtures/convergence/mos_series_r` is byte-identical.** This is
  the guard deck: `RD=12 RS=9`, the exact values behind the settled table's 3150
  bit mismatches, and its internal nodes are verified live. A partition that
  mis-sorted it, or a narrow basis leaking onto it, produces wrong currents here
  and nowhere else in the corpus.
- **256 of 256 fixture raws byte-identical**, and the exit codes of all 286
  decks in `benchmark/fixtures` match. `benchmark/capture_raws.sh` is the
  harness.
- `zig build test --summary all`: **261/261 steps, 407/407 tests**.
- `python3 benchmark/check_fixtures.py` verdicts unchanged on the categories
  that moved during development (`ngspice` 14/15 — `diffpair` is a pre-existing
  `UnsupportedAnalysisOutput`; `sweep` 7/7).

### The check that was left behind

`tests/devices.zig`, "collapse rank: a mixed batch narrows only the collapsed
instances". Builds an `RD=12 RS=9` mos1 twice — alone, and behind a collapsed
instance that forces the batch through the partition — and requires the stamps
bit-for-bit equal, plus that the collapsed instance added its four ports and no
internal node. Mutation-checked: forcing `partitionCollapsed` to claim every
instance collapses fails it.

The deck-level guard (`mos_series_r`) cannot cover this; a mixed batch needs two
different cards in one netlist.

## 5. What was NOT done, and why

- **No partial narrowing.** An instance that collapses `di` but not `si` runs at
  full width. Enumerating the 2^k flag combinations as comptime widths is a
  combinatorial explosion across 38 devices for a case no deck exhibits.
- **No GPU narrowing** (§3).
- **No `n_u > 8`** (§3).
- **`limitRange` untouched.** It is full width and carries no derivative, so the
  basis does not reach it. `canNarrow` refuses any basis where two unknowns in
  `limit_writes` share a lane, because `corr` is one entry per lane and could not
  hold two different corrections; mos1/mos6 write `{di, si}`, one per lane.

## Settled by this pass

| claim | the measurement |
|---|---|
| the collapsed case is rank 4 and narrowing it is sound | 256/256 raws byte-identical, `mos_series_r` included; −12.40% / −10.95% |
| the rank-4 merge is EXACT, not approximate | under `rd = 0` mos1 reads `x[d]`/`x[s]`/both flow unknowns nowhere, so their lanes are an identically-zero gradient; merging them into the alias's lane changes no FP operation |
| which lane member carries the stamp | lowest-alias is byte-identical; lowest-column drifts 4 decks (max 3.4e-9 abs) through shared-slot `+=` order |
| narrowing `diode` (n_u 4 → rank 2) | excluded by measurement already on record: inside one ymm, narrowing saves zero |
| the partition costs more than the narrowing saves | **no** — it is a setup-time `D.collapse` per instance and, on a uniform batch, zero data movement |

## Reproducing

```
zig build -Dgpu=false
valgrind --tool=callgrind --cache-sim=no --branch-sim=no \
  --callgrind-out-file=/dev/null zig-out/bin/espice -b --backend cpu \
  -r /tmp/o.raw benchmark/fixtures/scaling/parallel_inverters_100/circuit.sp

./benchmark/capture_raws.sh /tmp/raws-before    # then rebuild, then
./benchmark/capture_raws.sh /tmp/raws-after
diff /tmp/raws-before/exits.txt /tmp/raws-after/exits.txt
for f in /tmp/raws-before/*.raw; do cmp -s "$f" "/tmp/raws-after/$(basename $f)" || echo "DIFF $f"; done

ZP_TRAN_STATS=1 zig-out/bin/espice -b --backend cpu -r /tmp/o.raw DECK
ZP_OPDBG=1     zig-out/bin/espice -b --backend cpu -r /tmp/o.raw DECK | grep ladder:
```
