# AC analysis reads the source cards

`.ac` used to ignore the deck. `ac.zig:91` called
`sweep(..., ctx.source_branch, 1.0, 0.0, ...)` — magnitude and phase were
literals — and `ctx.source_branch` was whatever the *first* non-sensed `V` card
happened to be (`builder.zig:810`). `builder.zig:1843` parsed `AC mag [phase]`
only to `skip = 2` past it so those numbers were not mistaken for the DC value;
nothing in the tree stored an AC magnitude at all.

Every AC fixture that passed did so because its first `V` card was also the one
carrying `AC 1`. Six decks in the suite are not like that, and one of them is
driven by a *current* source, which the old shape could not express in any form.

## Semantics, confirmed against ngspice 44.2

Read from `/tmp/ng/ngspice-44.2`, not from memory.

| Claim | Source |
|---|---|
| Every device's AC load runs into ONE shared rhs pair, cleared once per point. | `src/spicelib/analysis/acan.c:471-490` (`CKTacLoad`: zero `CKTrhs`/`CKTirhs`, then `DEVices[i]->DEVacLoad` for every device type) |
| A V source drives its BRANCH row, and its ±1 branch stamps are unconditional. | `src/spicelib/devices/vsrc/vsrcacld.c:175-180` |
| An I source drives its two NODE rows, `+` on n+ and `−` on n−, with no branch unknown. | `src/spicelib/devices/isrc/isrcacld.c:43-50` |
| A card with no `AC` is still loaded — at zero. So a V source is an AC short, an I source an AC open. | `vsrcacld.c:171`, `isrcacld.c:37` read `acReal`/`acImag`, which stay 0 when `acGiven` was never set |
| Bare `AC` means mag 1, phase 0. `AC mag` means phase 0. | `vsrcpar.c:59-73` (2/1/0-argument fallthrough sets `acGiven`), `vsrctemp.c:38-43` (`acGiven && !acMGiven` → `acMag = 1`; `acGiven && !acPGiven` → `acPhase = 0`) |
| Phase is DEGREES; the excitation is `mag·e^{jφ}`. | `vsrctemp.c:68-70`, `isrctemp.c:64-66`: `radians = acPhase * M_PI / 180.0` |
| `.noise` does NOT use the card's AC spec — under `MODEACNOISE` only `ckt->noise_input` gets a unit drive, every other source gets zero. | `vsrcacld.c:160-166`, `isrcacld.c:28-35` |

Cross-checked by running ngspice on the probe decks (all five are now fixtures
under `benchmark/fixtures/ac/`): `AC 1` on the second of two V cards gives
`v(a)=0, v(b)=1`; `AC 3 45` gives `2.1213 + 2.1213j`; a deck with no `AC`
anywhere gives an identically zero response; bare `AC` gives `1+0j`.

## The change

**`builder.zig`** — a new SoA table beside `v_*`/`i_*`, filled only by cards that
name `AC` (existence-based, no `has_ac` flag):

```
ac_pos, ac_neg: []u32     ac_re, ac_im: []f64     n_ac: u32
```

`ac_pos`/`ac_neg` are the two rows an entry subtracts from / adds to under
`Circuit.rhs`'s residual sign (the AC solve's rhs is `−F`, since the Newton path
is `solveNeg(rhs, dx)`). An I card contributes `(n+, n−)`. A V card drives only
its branch row, so it lands as `(GROUND, branch)` — one untagged two-row loop
then covers both kinds, and `GROUND` rows are skipped because row 0 is the
ground clamp. `sourceAc()` parses the card with the ngspice defaults above;
`positionalNumber` returning null on the next keyword is what keeps
`AC 1 SIN 0 1 1k` from reading `SIN` as a phase.

A **sensed** V card (one an F/H/W element controls on) is not recorded. It stamps
nothing — the controlling 4-port model carries the branch instead — so its
recorded `br` is the row the *next* card got, and driving it would corrupt an
unrelated equation.

**`engine.zig`** — after the BBD permutation is applied to `ac_pos`/`ac_neg`,
`NetBuilder.acExcitation` collapses the table into one stacked-real vector
`[re(0..n), im(0..n)]` over the circuit unknowns, in the sim arena. That vector
IS ngspice's post-`CKTacLoad` `(CKTrhs, CKTirhs)` pair.

**`analysis/types.zig`** — `RunCtx.ac_drive: []const f64 = &.{}`.

**`ac.zig`** — `sweep()` takes `exc: []const f64` in place of
`(ac_branch, ac_mag, ac_phase_deg)`. Multi-source is now correct by
construction: it is one solve per frequency against a composite excitation, not
a special case layered on a single-branch poke. Empty `exc` is a zero response.

`sp.zig` and `stb.zig` needed no change — neither calls `ac.sweep`. `sp.zig`
builds its own per-port unit rhs; `stb.zig`'s `ctx.source_node` is a loop-probe
insertion point, not a drive. `noise.zig` has no input source at all (it emits
output noise only), which matches ngspice's `MODEACNOISE` behaviour above.

## The no-AC-source decision

**A deck that runs `.ac` with no card naming `AC` now produces a zero response**,
matching ngspice (verified: `ac/no_ac_source`). Previously espice drove the first
V card at 1∠0°, which is a value ngspice never produces.

The audit's claim that "every currently-passing AC fixture has an explicit `AC 1`
on the first card" is **false**. Verified across all 61 `.ac`/`.sp`/`.stb`/
`.noise`/`.pz`/`.tf`/`.disto`/`.sens` fixtures; the exceptions are listed below.
No fixture relied on the implicit poke, though — `ac/no_ac_source` is the only
no-AC-source `.ac` deck and it is new.

## Adjacent defects seen, not fixed

- **`sp.zig` port selection.** `portnum` and `z0` appear nowhere in `builder.zig`
  or `engine.zig` — grep confirms zero references. `.sp` job construction never
  sets `opts.ports`, so `sp.run` always falls back to the single
  `(ctx.source_node, ctx.source_branch)` port at the default z0 = 50, and the
  `VP2 out 0 DC 0 portnum 2 z0 50` card is stamped as a plain 0 V source, i.e. an
  AC short on `out`. This change does not entrench it: `ac_drive` and
  `opts.ports` are independent, and populating `ports` from the cards is still
  the whole fix.
- **`disto.zig:124`** drives `rhs_work[options.ac_source_node]` — a NODE row.
  For a V card that row is clamped by the branch equation, so the poke is lost.
  `pac.zig:112` has the same shape (`exc_row = n_harm * n + ac_source_node`).
  Both also read `ctx.source_node`, i.e. the first V card, not the card carrying
  `AC` or `DISTOF1`.
- **`ngspice/res_partition`** deviates by 0.25 before and after: `r2 2 0 5K ac=15k`
  uses ngspice's AC-only resistance override, which espice ignores.
- **`devices/urc_ac`** does not emit the URC internal lump nodes ngspice names
  (`v(u1#hi1)` and 18 more), so those signals go uncompared.
