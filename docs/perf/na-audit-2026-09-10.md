# N/A audit — the 64 unvalidated fixtures, 2026-09-10

`docs/perf/baseline-446268a.md` reports 154 PASS / 7 FAIL / 64 N/A / 23 SKIP.
An N/A is a fixture the comparator refused to score. It reads like a pass in
every summary, so a quarter of the suite has never been checked against
ngspice at all. This itemizes all 64: which branch of `comparePlots` /
`parseRawBlob` fired, why, and what has to change.

Method: re-ran all 64 as the runner does
(`zig-out/bin/espice -b --backend cpu -r X.raw <deck>`, `ngspice -b -r X.raw
<deck>`), then replayed the runner's decision tree — including the edge-phase
window at runner.zig:519-538 — against each raw pair. The replay reproduces
the runner's published max/rms to every printed digit on the 20 fixtures that
carry numbers (`tline/cpl3_4_line` 1.72e0/9.21e-1, `devices/cswitch`
1.00e-15/7.02e-16, `devices/vbic_forced_output` 4.76e-3/1.33e-3, ...), so the
"would-be verdict" figures below are the runner's arithmetic, not a
re-derivation.

## B2 — the defects, with mechanism

### 1. AC excitation is on the wrong source, at the wrong magnitude

`src/analysis/ac/ac.zig:78-91` says it plainly:

```
/// Contract entry: unit excitation on the first source branch, ...
try sweep(ctx.circuit, x_op, ctx.source_branch, 1.0, 0.0, ctx.probes, ...);
```

`ctx.source_branch` is set at `src/builder.zig:810-813` to the **first
non-sensed V card in the deck**. The card's `AC <mag> <phase>` never reaches
the sweep — 1.0 and 0.0 are literals.

Two-source probe, `V1 a 0 DC 1` then `V2 b 0 DC 0 AC 1`:

| deck | ngspice v(a), v(b) | espice v(a), v(b) |
|---|---|---|
| AC on second card | 0, 1 | **1, 0** |
| AC on first card | 0, 1 | 0, 1 |
| explicit `AC 0` on the first card | 0, 1 | **1, 0** |
| single card `AC 3 45` | 2.121 + 2.121j | **1 + 0j** |

Every AC fixture that PASSes today has exactly one V card, and it is both first
and `AC 1` — which is why nine complex fixtures score 1e-13 or better and five
score 2.0. The same `ctx.source_branch` feeds `sp.zig:192` and `stb.zig:159`.

### 2. `.sp` ignores `portnum` / `z0`

`sp.zig:222` falls back to `one_port` when `opts.ports` is empty, and it is
empty for every fixture in `sp/` — the V-card `portnum 1 z0 50` /
`portnum 2 z0 50` never reaches it. Port 2 therefore stays a plain 0 V source,
i.e. a short to ground, and only S11 is emitted (nvars = 2 against ngspice's
19).

The shorted port is measurable, not inferred. `sp/pi_attenuator`: with port 2
terminated in 50 Ω, Zin = 150 ∥ (37.5 + 150∥50) = 50 → S11 = 0, which is what
ngspice gives. With port 2 shorted, Zin = 150 ∥ 37.5 = 30 → S11 = −0.25, which
is what espice gives, at every frequency. `sp/rc_twoport`: espice reports
0.904762 at 1 MHz *and* 1 GHz — Zin = 1000 Ω exactly, i.e. R1 alone with C1
shorted by the grounded port. ngspice sweeps 0.909087 → 0.904767.

### 3. `.noise` has no resistor thermal noise, and different units

`Circuit.collectNoiseSources` (Circuit.zig:637-642) walks `b.hooks.collect_noise`,
which `engine.zig:1312` installs only for models declaring `noise_gens`. 16 of
the 39 `.va` models declare one; `resistor.va` and `diode.va` do not. A deck
whose only noise sources are resistors therefore returns **exactly zero**:

| fixture | espice onoise | ngspice onoise_spectrum |
|---|---|---|
| golden/noise (1k + 3k) | 0 at all 21 points | 3.526e-9 |
| noise/rc_noise (100k + 100p) | 0 at all 141 points | 6.48e-11 … 4.071e-8 |
| noise/resistor_noise (10k + 10k) | 0 | 9.104e-9 |
| noise/amp_noise (BJT + 100k + 4.7k) | 1.162e-16 | 1.166e-8 |

Separately, `noise.zig:100-103` accumulates `|H|²·psd` and writes it straight
out, so `onoise_density` is V²/Hz where ngspice's `onoise_spectrum` is V/√Hz
(check: 4kT·5k = 8.29e-17, √ = 9.10e-9 = ngspice's `resistor_noise` figure).
espice also emits no `inoise_spectrum` and no `Integrated Noise` plot, so 3 of
ngspice's 5 noise columns have no counterpart at all.

### 4. `.disto` emits zeros

All four disto fixtures: `hd2`, `v1_mag`, `v2_mag` are 0.0 at every point (6,
31, 21 and 31 points). `disto.zig:124` stamps the drive as
`rhs_work[options.ac_source_node] = options.ac_magnitude` — a current into a
**node** row, where `ac_source_node` defaults to `ctx.source_node`
(disto.zig:185). That node is held by the drive V source, so its branch
equation pins it and the first-order solve returns V1(out) = 0. `v1_mag` is
then 0, and the `v1_out_mag > 1e-30` guard at disto.zig:168 collapses `hd2` to
0 as well. This is the same hole as the two known-failing `tests/analyses.zig`
HD2 cases (AGENTS.md "Verification"), but it is total, not a tolerance miss.

The output shape also differs from ngspice's — ngspice writes two complex plots
of node voltages at 2f and 3f — so even a fixed `.disto` needs a semantic
bridge (`hd2 = |V₂(out)| / |V₁(out)|`), not a shape fix. That part is the one
genuine B4 left in the tree.

### 5. Hierarchical node names are reversed

`src/frontend/parser.zig:995`:

```zig
nd.name = try std.mem.concat(arena, u8, &.{ sd.name, ".", d.name });
```

`d` is the X card being expanded, `sd` the device inside the subckt body. SPICE
names the flattened device `<outer instance>.<inner>`; this builds
`<inner>.<outer>`. Recursion compounds it, and `mapNode` (parser.zig:882)
prefixes nodes with `d.name`, so node names inherit the reversal.

Proof, `ngspice/fourbitadder` (4 levels deep, 271 columns each side): 207 of
ngspice's names have no espice match. Reverse the instance segments of every
espice name and the mismatch is **0 in both directions** — the sets are
identical. Compare all 270 data columns after that alignment: worst max error
1.586e-4, well inside PASS. The numbers were always right; only the labels were
backwards. The fix is the argument order on line 995.

### 6. No branch current for E / F / G / H / B / W

`src/engine.zig:254-259` registers probes for V cards and inductors only, and
skips V cards flagged `sensed`:

```zig
for (nb.v_names[..], nb.v_branches[..], nb.v_sensed[..]) |name, br, sensed| {
    if (sensed) continue;
```

Two gaps fall out. First, controlled sources that carry an MNA branch in both
simulators (E, H, B) get no `i(...)` column at all — ngspice emits `i(e1)`,
`i(h1)`, `i(b1)`. Second, a V card used as an F/H/W current sensor is marked
`sensed` at builder.zig:799-806 (the 4-port model carries its own
`branch (cp,cn) ctrl` in its place) and is dropped from the probe list, so
`i(vam)` disappears. Probe confirms it is the *sensing*, not the value:

| deck | espice columns |
|---|---|
| `Vzero mid 0 DC 0`, unreferenced | `i(vin), i(vzero), v(in), v(mid)` |
| same card referenced by `F1 ... Vam 2` | `i(vin), v(in), v(sense), v(out)` |
| same, `DC 0.001` | `i(vin), v(in), v(sense), v(out)` |

The current exists — it is the controlling model's `ctrl` branch. The recorded
`v_branches[n_v]` (builder.zig:790, `br = self.b.n` taken *before* an addDevice
that never happens) is not that branch, which is why the row reads as
unallocated.

### 7. `ac=` on a resistor is ignored

`ngspice/res_partition` sets `r2 2 0 5K ac=15k`. ngspice uses 15 k in AC and
5 k in DC; espice uses 5 k in both, giving v(2) = 0.5 against ngspice's 0.75.
`addPassive` maps only `r`/`resist`, and `resistor.va` has no `ac` parameter.

### 8. `.sens` columns are keyed by device-class ordinal

espice writes 175 columns named `vsource#0.dc`, `resistor#0.r`,
`vsource#0.pwl_timesZ5b0Z5d`, …; ngspice writes 53 named `v(vin)`, `v(r1)`,
`v(r1_m)`, `v(r1_scale)`, `v(r2:tc1)`. `resistor#N` is not resolvable to a card
name from the raw file, so this cannot be fixed in the runner. The values are
right — `sens/voltage_divider` matches on all three nonzero entries (0.75,
−0.001875, 6.24999e-4), `sens/bridge` on all five, `sens/rc_lowpass` on all
three. Also secondary-B4: ngspice's per-instance `_m` / `_scale` / `_temp`
sensitivities have no espice counterpart, so even after renaming, sens needs
intersection-only scoring.

## B1 — the runner changes, ranked

"Moves off N/A" counts fixtures that go from unscored to scored, B1 and B2
alike — a B2 fixture that becomes a FAIL is still a fixture the runner now
checks. Several fixtures need two changes; the third column is what each change
adds once the ones above it have landed.

| # | change | site | moves off N/A | cumulative | of which FAIL |
|---|---|---|---:|---:|---:|
| 1 | **Compare complex plots** re/im-wise with the existing per-column normalization | runner.zig:439 | **14** | 14 | 5 |
| 2 | **Match plots by name across multi-plot raws**; score every plot present in both, require ≥1 | runner.zig:400 + 439 | **10** | 24 | 2 |
| 3 | Ignore reference columns whose name is duplicated within the plot | runner.zig:450 | 5 | 29 | 3 |
| 4 | Alias the `.tf` column names | runner.zig:420 | 4 | 33 | 0 |
| 5 | Widen the internal-branch exemption past `#`/`:` | runner.zig:487 | 2 | 35 | 1 |
| 6 | Relative epsilon on the transient span guard | runner.zig:466 | 1 | 36 | 0 |
| 7 | Missing reference raw → reference SKIP, not N/A | runner.zig:301 | 1 → SKIP | 37 | 0 |

**Changes 1 and 2 are the whole story: 24 of the 64, a third of the N/A column,
from two edits.** Both also convert the largest silent blocks into real signal —
1 alone turns `bjt/common_emitter`, `devices/diode_capacitance` and the three
`sweep/opamp_wl_*` from unchecked into five concrete FAILs, all five tracing to
the same AC-source defect.

Change 1 is small: `parseRawBlob` already reads `is_complex` and sizes the
buffer at `2 * nvars * npoints`, so the data is there; `comparePlots` refuses it
at one `if`. Feed each column's re and im through the existing error path and
take the worse. Do **not** collapse to magnitude first — a phase-convention
error would then read as a pass.

Change 2 is the bigger edit but structural, not subtle: `parseRawBlob` returns
one `Plot` and bails on trailing bytes (runner.zig:399-400, already carrying a
`ponytail:` note saying exactly this). Return `[]Plot`, key by lowercased
plotname, iterate the intersection. Plot **order differs between the two engines
on every multi-analysis deck** (espice writes Operating Point first, ngspice
writes AC first), so index-matching would be wrong — it must be by name.
`fourier/*` and `golden/four` also need "espice-only plots are not a failure":
espice writes a `Fourier Analysis` plot into the raw where ngspice prints
`.four` to stdout.

Changes 3 and 5 need a guard rail. A blanket "unknown `i(...)` is exempt" rule
would swallow the E/H/B/sensed-source gap in B2 as well, converting eight real
defects into silent passes. Scope 5 to reference columns naming a card whose
letter is not `V`, `L`, `E`, `F`, `G`, `H`, `B` or `W`; scope 3 to names
appearing more than once in the same plot header.

Not on this list, deliberately: `sp/*`, `noise/*`, `disto/*` and `sens/*` also
sit behind C1/C2/P5, but no runner change validates them, because espice emits
the wrong columns (S11 only; no `inoise`/totals and wrong units; zeros;
ordinal-keyed parameter names). They are counted in B2, not here.

## Reproducing

The raws are in `/tmp/naudit/raw/<category>--<name>.{ng,zp}.raw` and the
branch-replay scripts in `/tmp/naudit/` (`branch.py` prints the firing branch,
`multi.py` the by-name multi-plot verdict with the edge window). Neither is
checked in — they exist to be thrown away once the runner does this itself.
